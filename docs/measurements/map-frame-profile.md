# Профиль кадра карты (PURRGO_RENDER_PROF), ноябрь 2026

Замер на железе (STM32U585 на 80 МГц, SD по SPI, карта из `roads/water/landuse/waterways/pois`),
строки `PROF`, `PROF2`, `PROF3`, `PROF4` ([README](README.md)). 40+ кадров на масштабах 3-11 до
изменений ниже и 18 кадров с трассой секторов.

## Из чего состоит кадр

| Статья | Доля кадра | Стоимость единицы |
|---|---|---|
| проекция (`proj`) | 1-3,5% | ~2,1 мкс на точку |
| заливка полигонов (`fill`) | до 15% (масштаб 8), обычно 5-6% | ~0,3 мс на полигон |
| линии (`lines`) | 5-7% на лёгких кадрах, 23% на самых плотных | ~22 мкс на сегмент |
| чтение имён из `.db` (`name`) | до 3,3% | ~0,29 мс на чтение |
| остаток (`other`: SD, обход индекса, разбор) | 72-92% | - |

Внутри `other` почти всё - чтение SD: `sd` составляет 91-93% кадра на масштабах 3-4, 80-85% на 5-6,
55-60% на масштабах 7-11. Кадр на масштабе 3 (~330 мс) - это ~475 команд чтения SD, из них ~460 на `.idx`
пяти слоёв (для ~30 видимых объектов).

## Модель стоимости SD

`sd ≈ 441 мкс × команд + 235 мкс × секторов` (по 18 кадрам, ошибка до 7%). Согласуется с
[SD-speed-test-result.txt](SD-speed-test-result.txt): 1 сектор ~0,68 мс, блок из 8 секторов ~2,3 мс.
CLMT работает (средний seek+read 0,63-0,67 мс, `max` не больше 1,7 мс).

## Что дали и не дали идеи (модель на трассе кадра)

- Кэш секторов внутри кадра (256 или 768 вместо 64): 0-8%, медиана ~1%. Каждый сектор индекса читается за
  кадр один раз (`miss` = `dist` у всех `.idx`).
- Read-ahead 8 для `.idx` без условий: медиана ×0,56 (вредно). Доля промахов подряд у `roads.idx`:
  26% (масштаб 3), 32% (4), 62% (5), 89-93% (10-11).
- Модель считает каждый кадр с пустым кэшем; реальный кэш при 64 секторах ничего не держал между кадрами
  (n у `sd` = `cmd` у `ccur`).

## Решения

- Проекцию, `fill_span` для остальных примитивов (кроме линий), кэш `.db` не делаем.
- Сделано: адаптивный read-ahead для `.idx` (растёт только пока промахи идут подряд), кэш секторов 768
  штук в общей арене RAM (живёт между кадрами), ускорение линий (прямая запись в 2-bpp буфер, отрезки на
  длинных пологих линиях).
- Холодные промахи индекса уменьшит только новая раскладка (PGO V4): [pgo-v4.md](../design/pgo-v4.md).
