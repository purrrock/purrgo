# microSD в SPI-режиме (STM32U585)

Заметка к этапу 4.3 `TODO_migrate.md`. В корпусе UFQFPN48 у STM32U585CI нет SDMMC, поэтому
используется SPI-режим карты (SPI2: PB13 SCK, PB14 MISO, PB15 MOSI,
PB12 CS, PB10 Detect). Реализация: `apps/stm32/common/sd_spi` (протокол, без HAL, host-тест
`tests/host/test_sd_spi.c`) и `apps/stm32/PurrGO_STM32U5/Core/Src/sd_card.c` (привязка к HAL, FatFs).

## Особенности SPI-режима

| Что | SPI-режим |
|---|---|
| Линии | MOSI, MISO, SCK, CS |
| Частота | не более 25 МГц на 1 бите |
| Теоретический предел | ~1.25 МБ/с на 10 МГц, ~2.5 МБ/с на 20 МГц |
| Команды | подмножество: CMD0, CMD8, CMD9, CMD12, CMD16, CMD17/18, CMD24/25, CMD55, CMD58, ACMD23, ACMD41 |
| CRC | по умолчанию выключен (CRC обязателен только для CMD0 и CMD8) |
| Занятость карты | линия MISO удерживается в 0 |
| Адресация | блоками у SDHC/SDXC, байтами у SDSC |

Цифры производительности - оценки по частоте шины, без накладных расходов HAL и карты; реальные
значения нужно замерять на плате (этап 7).

## Что важно в реализации

- После включения питания карта получает не менее 74 тактов при высоком CS и только потом CMD0.
  Инициализация идёт на частоте не выше 400 кГц (SPI2 `/256` = 312.5 кГц при SYSCLK 80 МГц), рабочая
  частота включается после успешной идентификации (`PURRGO_SD_SPI_RUN_PRESCALER`, по умолчанию
  `/8` = 10 МГц).
- Линия MOSI во время чтения удерживается в 1 (`0xFF`), чтобы карта не приняла данные за команду.
- Подтяжка DAT3 (CS) к 3.3 В на модуле держит карту в режиме SD (а не SPI) до первого CMD0
  с низким CS: сам модуль с подтяжкой подходит, дополнительные резисторы не нужны.
- Перед каждой командой ожидается освобождение линии (`0xFF`), каждое ожидание ограничено по
  времени, поэтому извлечение карты во время обмена возвращает ошибку, а не зависает. После
  ошибки обмена при снятом Detect или при таймауте карта объявляется потерянной, `purrgo_sd_poll()`
  размонтирует файловую систему и при следующей вставке монтирует заново.
- Карты MMC и карты v1 с несовместимым напряжением не поддерживаются (возвращается
  `SD_SPI_ERR_UNSUPPORTED`).

## Как ускорить, если чтения карты не хватит

1. Поднять частоту: `PURRGO_SD_SPI_RUN_PRESCALER` = `SPI_BAUDRATEPRESCALER_4` (20 МГц), если позволяет
   проводка (на макете с проводами стабильнее 10 МГц).
2. Читать секторы пачками (`f_read` с кратным 512 размером и выровненным буфером превращается в CMD18).
3. Передавать блок по SPI2 через GPDMA вместо опроса (опция, пока не реализована).
