# TODO: Доработка и оптимизация проекта PurrGO

Данный документ описывает задачи по развитию PurrGO и рефакторингу бинарного формата векторных карт.

Основные цели:

- адаптация формата карт под STM32 Cortex-M;
- минимизация потребления RAM;
- отсутствие `float`/FPU-зависимых вычислений в навигаторе;
- потоковое чтение геометрии;
- уменьшение объёма бинарных данных;
- отделение собственного формата PurrGO от исходного формата DT G1;
- дальнейшее развитие map renderer и offline-конвертера.
- реализация динамического отображения позиции GNSS и энергоэффективного обновления дисплея.

### 3.2. SQT / LOD. Реализовано.

Карты уже содержат три уровня детализации:

- `LOD 0` — наиболее детальная геометрия.
- `LOD 1` — средняя детализация.
- `LOD 2` — минимальная детализация.

Сейчас навигатор использует только `LOD 0`.

- [X] **Реализовать выбор LOD в зависимости от масштаба карты.**
  - Использовать `LOD 0` при масштабе **до 500 м включительно**.
  - Использовать `LOD 1` при масштабе **свыше 500 м до 5 км включительно**.
  - Использовать `LOD 2` при масштабе **свыше 5 км**.
  - Навигатор должен выбирать соответствующий SQT block до начала обхода его дерева.
  - Не обрабатывать одновременно несколько LOD.
  - Не загружать и не парсить геометрию LOD, которая не используется для текущего масштаба.
  - Определить точный способ получения текущего масштаба из camera/viewport и зафиксировать его в map subsystem.
  - Границы выбора должны быть детерминированными:
    `<= 500 м` → LOD 0,
    `> 500 м && <= 5 км` → LOD 1,
    `> 5 км` → LOD 2.
  - Проверить корректность выбора LOD при изменении масштаба карты в обе стороны.
