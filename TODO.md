# TODO: Доработка и оптимизация проекта PurrGO

Данный документ описывает задачи по развитию PurrGO и рефакторингу бинарного формата векторных карт.

Основные цели:

- адаптация формата карт под STM32 Cortex-M;
- минимизация потребления RAM;
- отсутствие `float`/FPU-зависимых вычислений в навигаторе;
- потоковое чтение геометрии;
- уменьшение объёма бинарных данных;
- отделение собственного формата PurrGO от исходного формата DT G1;
- дальнейшее развитие map renderer и offline-конвертера.

---

## 4. Ограничения `.mlp` и потоковое чтение геометрии

C-parser уже использует потоковое чтение точек для line geometry, однако polygon rendering требует временного массива projected points.

- [ ] **Определить окончательный лимит geometry.**
  - Зафиксировать `PURRGO_MAP_MAX_POINTS`.
  - Зафиксировать `PURRGO_MAP_MAX_PARTS`.
  - Значения должны соответствовать реальному доступному RAM
    целевой STM32-платформы.
  - Не считать эти значения ограничениями самого бинарного формата, если они являются только ограничениями renderer.

- [ ] **Реализовать автоматический chunking line geometry.**
  - Ограничить количество вершин одного chunk.
  - Повторять граничную точку в следующем chunk.
  - Не допускать визуальных разрывов между chunks.
  - Сохранять корректную работу `parts[]`.

- [ ] **Реализовать subdivision polygon geometry.**
  - Не разрезать polygon простым делением массива точек.
  - Каждый ring должен сохранять геометрическую целостность.
  - Сохранять outer rings и holes.
  - При необходимости использовать clipping/subdivision на стороне PC.
  - Навигатор не должен выполнять сложную геометрическую фрагментацию.

- [ ] **Устранить необходимость в чрезмерно большом статическом
  polygon buffer**, если после chunking это станет возможным.

- [ ] **Проверить поведение renderer на geometry, выходящей за viewport.**
  - Не допускать переполнения координат.
  - Сохранять integer-only projection.
  - Проверить antimeridian handling.
