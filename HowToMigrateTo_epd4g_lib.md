# Переход E-Ink на библиотеку epd4g

Драйвер Waveshare (`EPD_2in7_V2.c`, `DEV_Config.c`, сабмодуль `third_party/e-Paper`) заменён на
библиотеку [`epd4g`](https://github.com/purrrock/eink_part_refresh) (4-gray partial, fast full,
1-bit режим, неблокирующий API). Документ описывает, как это подключено, и что надо знать при
доработке. Состояние: код собирается, host-тест очереди обновлений проходит; **на железе не
проверено** (см. «Проверка на железе»).

## Подключение библиотеки
Сабмодуль `third_party/eink_part_refresh` (используется только каталог `epd4g/`):

```sh
git submodule deinit -f third_party/e-Paper
git rm -f third_party/e-Paper                 # убирает и запись в .gitmodules
rm -rf .git/modules/third_party/e-Paper
git submodule add https://github.com/purrrock/eink_part_refresh third_party/eink_part_refresh
```

В `apps/stm32/PurrGO_STM32U5/CMakeLists.txt`: `add_subdirectory(.../epd4g)` и `epd4g` в
`target_link_libraries`. Это INTERFACE-библиотека: исходники компилируются внутри таргета прошивки,
поэтому видят `main.h`, HAL, `hspi1` и метки `EINK_CS/DC/RST/BUSY` из CubeMX (порт
`epd4g_port_stm32_hal.c`). Изменений в `.ioc` не требуется. Определение `EPD4G_BW_THRESHOLD=3`
сохраняет прежнюю семантику 1-bit режима: белый → белый, любой серый → чёрный (меню и экран
выключения двухцветные; по умолчанию в библиотеке порог 2, светло-серый стал бы белым).
Библиотека в `purrgo_sources_warnings` не входит; для контроля она проверена с
`-Wall -Wextra -Wconversion -Wshadow` (предупреждений нет).

## Устройство в PurrGO
| Файл | Роль |
|---|---|
| `include/purrgo/display_hal.h` | новый `display_set_mode(DISPLAY_MODE_GRAY4 / DISPLAY_MODE_MONO)`; `display_refresh()` и `display_flush()` стали неблокирующими, `display_sleep()` блокирующая |
| `src/core/app_ui.c` | режим выбирается по экрану: карта — 4 gray, остальное — 1 bit; экран выключения всегда 4 gray |
| `common/Src/display_eink.c` | очередь обновлений поверх epd4g (см. ниже) |
| `common/Src/display_stm32.c` | framebuffer, накопление области, `display_stm32_poll()`, `display_stm32_ready_for_render()` |
| `common/Src/stm32_app.c` | `display_stm32_poll()` на каждом проходе цикла; рендер только при `display_stm32_ready_for_render()` |
| `common/Src/eink_test.c` | самотесты через `display_eink`/epd4g (`PURRGO_EINK_SELFTEST_4GRAY`, `PURRGO_EINK_SELFTEST_PARTIAL`) |
| `tests/host/test_display_eink.c` | host-тест очереди на модели панели (нужен сабмодуль) |

Framebuffer PurrGO (176×264, 2 бита, первый пиксель в старших битах, 0 = чёрный … 3 = белый)
совпадает с буфером epd4g, конвертации и поворота нет. Меню в 1-bit режиме выводятся прямо из
него (`EPD4G_SRC_2BPP`), второй буфер не нужен.

### Логика `display_eink.c`
- Одно обновление в работе. `display_refresh()` / `display_flush()` только ставят запрос; пока
  идёт предыдущее, запросы сливаются (полное перекрывает частичное, области объединяются).
  Запуск из очереди — в `display_eink_poll()`.
- Рендер запрещён, пока `epd4g_data_busy()` (передача кадра по SPI, десятки мс). Волна панели
  (секунды) рендеру не мешает: драйвер уже всё получил.
- Первое обновление, смена режима, потеря картинки (ошибка) и лимит частичных подряд
  (4 gray — 8, 1 bit — 5) дают полное обновление. Смена режима панели невозможна без
  `epd4g_init()` / `epd4g_bw_init()`; это делается автоматически.
- 4 gray: перерисовываются только пиксели, отличающиеся от буфера `prev` (11616 байт,
  «что на панели»). Сравнивается весь кадр, а не накопленная область: так нельзя потерять
  изменение, которое экран забыл отметить. `prev` обновляется сразу после старта задания (кадр
  в этот момент уже зафиксирован).
- 1 bit: частичное обновление окна накопленной области.
- Простой 1 с → `epd4g_start_sleep()` (в 4 gray это ещё и power off). Следующее обновление
  разбудит панель: в 4 gray через `epd4g_init()` (картинка на панели сохраняется, обновление
  остаётся частичным), в 1 bit аппаратным reset внутри частичного обновления.
- Ошибка (например, таймаут BUSY): панель считается потерянной, запрос ставится заново как
  полное обновление, повтор через 2 с.
- `display_sleep()` (выключение питания): ждёт все поставленные обновления (в том числе
  `display_refresh()` экрана выключения), затем `epd4g_sleep()`; с ограничением 30 с.

## Что исправлено относительно первой версии этого документа
1. **SPI.** «42 МГц» — это значение F411 (84/2). На U585 делитель 2 даёт ~40 МГц, делитель 8 —
   10 МГц; `display_eink_init()` ставит `/8` (`PURRGO_EINK_SPI_PRESCALER`).
2. **`power_stm32.c` менять не нужно.** Последовательность выключения в ядре:
   `display_refresh()` → `display_sleep()` (`src/core/power.c`). Блокирующее ожидание теперь внутри
   `display_sleep()`. Но экран выключения — это карта, а рисуется он без смены экрана, поэтому
   `purrgo_app_ui_render_power_off()` сам вызывает `display_set_mode(DISPLAY_MODE_GRAY4)`
   (при выключении из меню режим иначе остался бы 1-bit).
3. **Недостаточно запускать `epd4g_start_*` из `display_flush()`.** `epd4g_data_busy() == 0`
   не значит `epd4g_is_busy() == 0`: рендер разрешён, а библиотека ещё занята волной, и
   `epd4g_start_*` вернёт `EPD4G_ERR_BUSY`. Нужна очередь запросов (см. выше).
4. **Режим панели 4 gray / 1 bit не переключается «на лету»:** перед первым обновлением в другом
   режиме нужны `epd4g_init()` / `epd4g_bw_init()` и полное обновление; после `epd4g_sleep()` в
   4 gray снова нужен `epd4g_init()`, а повторный `epd4g_sleep()` вернёт `ERR_NOT_INIT`.
5. **`prev` и области.** `epd4g_fb_copy_rect()` копирует целые байтовые столбцы (по 4 пикселя):
   если обновлять `prev` по произвольной области, соседние пиксели того же байта попадут в
   `prev`, хотя на панель не выводились. Поэтому для 4 gray используется сравнение всего кадра и
   копирование всего буфера.
6. **Маршрутный компьютер не регистрировал изменённые области** (значения менялись, а на панель
   уходила только строка подсказок кнопок). В `app_ui.c` после отрисовки значений добавлено
   `display_refresh_region(весь экран)`.
7. Заставка: `HAL_Delay(300)` убрана, `display_refresh()` не блокирует; первый кадр карты встаёт
   в очередь за заставкой (заставка в 1-bit, карта в 4 gray: два полных обновления при старте, как и раньше).
8. Удалены `PURRGO_EINK_MODE_*`/`PURRGO_HW_EINK_MODE` (режим выбирается по экрану),
   `DEV_Config.c/.h`, `Debug.h`.

## Результат проверки библиотеки
Всё необходимое для PurrGO в `epd4g` реализовано (4 gray full/partial по diff, 1-bit full/partial
окном, неблокирующий API, sleep/power off, `data_busy`); доработок библиотеки для подключения не
потребовалось. Её host-тесты (`make -C epd4g/tests`) проходят. Замечания без блокировки:
- `epd4g_start_sleep()` в 4 gray второй раз возвращает `ERR_NOT_INIT` (в 1 bit — `OK`);
  можно сделать идемпотентным, слой PurrGO это учитывает сам.
- `epd4g_fb_copy_rect()` — см. п. 5; стоит отметить в README библиотеки (уже есть упоминание в `epd4g_fb.h`).
- 1-bit режим, deep sleep и power off в README библиотеки помечены как непроверенные на железе.

## Проверка на железе
1. `PURRGO_EINK_SELFTEST_4GRAY` (4 полосы серого, шахматка, градиент) — картинка без мусора.
2. `PURRGO_EINK_SELFTEST_PARTIAL`: 1-bit квадраты без мигания; затем 4 gray, квадраты четырёх оттенков.
3. Приложение: запуск → заставка → карта; открытие меню (вход в 1-bit: одно полное мигание),
   перемещение курсора по CONFIG (частичное без мигания, нет «залипших» инвертированных строк),
   возврат на карту, движение маркера (частичное 4 gray), выключение из карты и из меню
   (экран выключения в 4 gray).
4. Ghosting: после 8 частичных 4 gray и 5 частичных 1 bit должно быть одно полное обновление.
5. Ток в простое после засыпания панели (пока не измерялся).

Параметры в `display_eink.c` (переопределяются `-D`): `PURRGO_EINK_SPI_PRESCALER`,
`PURRGO_EINK_GRAY_PARTIALS_BEFORE_FULL`, `PURRGO_EINK_MONO_PARTIALS_BEFORE_FULL`,
`PURRGO_EINK_GRAY_FULL_MODE` (`EPD4G_FULL_FAST` ~3 с / `EPD4G_FULL_DEEP` ~5 с),
`PURRGO_EINK_MONO_FULL_MODE`, `PURRGO_EINK_SLEEP_AFTER_MS`.

## Чего по-прежнему нет
- Прерывание EXTI по BUSY вместо опроса: пока главный цикл просыпается по SysTick (1 кГц).
- SPI через DMA: не нужен, пока `epd4g_poll()` укладывается в миллисекунду (CS и D/C
  переключаются пачками, а не на каждый байт, как в драйвере Waveshare).
- Цвет серого в 1-bit режиме (серые заливки `landuse` дают чёрное) — отдельный пункт в `TODO_refact.md`.
