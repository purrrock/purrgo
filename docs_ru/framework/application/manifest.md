
# manifest 文件

`manifest.json` 文件中包含了应用描述、接口声明、页面路由等信息。

`manifest.json` 是一个 JSON 文件，且文件内容必须是一个 JSON Object，本文档会介绍 `manifest.json` 各个字段的功能。

## 字段说明

### 根属性

这些字段是 `manifest.json` 文件根 JSON 对象的属性。

::: details 类型签名
``` ts
interface Manifest {
  package: string,
  name: string,
  icon: string,
  versionName: string,
  versionCode: number,
  config?: Config,
  permissions?: PermissionInfo[],
  router: Router,
  display?: Display,
  dial?: Dial,
  widgets?: Widget[]
}
```
:::

#### `package` <decl type="string" />

Поле «пакет» — это имя пакета приложения и является обязательным полем. Рекомендуется использовать формат com.company.module, например: com.example.demo. Имена пакетов приложений в системе должны быть уникальными.

::: важно
Магазины приложений многих производителей устройств не поддерживают тире `-` в именах пакетов, поэтому избегайте их использования. Мы также не рекомендуем вместо этого использовать подчеркивания `_` или `.`, в этом случае соедините слова напрямую, например `com.wateralert.demo`.
:::

#### `name` <decl type="string" />

Отображаемое название приложения, обязательное поле. В пределах 6 китайских иероглифов, соответствующих имени, сохраненному в магазине приложений, используется для отображения имени приложения на значках на рабочем столе, во всплывающих окнах и т. д. На это поле можно ссылаться с помощью выражения `${}` для [интернационализированной строки](i18n.md), например:
``` JSON
{
  "name": "${appName}"
}
```
где `appName` — это ключ интернационализированной строки. Интернационализированные имена приложений позволяют в списке приложений устройства отображать названия приложений на текущем языке вместо фиксированного языка.

#### `icon` <decl type="string" />

Путь к значку приложения, например `/assets/icon.png`.

#### `versionName` <decl type="string" />

Строка версии приложения.

#### `versionCode` <decl type="number" />

Код версии приложения представляет собой целое число. Рекомендуется увеличивать код версии на единицу каждый раз при публикации приложения.

#### `config` <decl type="?: Config" />

Дополнительные поля, описывающие информацию о конфигурации системы, см. в разделе [объект Config](#config-object).

#### `permissions` <decl type="?: PermissionInfo[]" />

Массив объектов PermissionInfo, представляющий список разрешений, используемых приложением. Когда приложению требуется доступ к информации о местоположении, датчикам, информации об устройстве, записи, Bluetooth, данным о состоянии здоровья и т. д., ему необходимо объявить соответствующие разрешения в этом поле, например:

``` JSON
{
  "разрешения": [
    { "name": "watch.permission.LOCATION" },
    { "name": "watch.permission.RECORD" }
  ]
}
```
Объект PermissionInfo описывает информацию о разрешениях, необходимую приложению. В настоящее время он имеет только одно поле `name`. Его подпись следующая:
``` тс
typePermissionInfo = {
  имя: строка; // Имя разрешения, уникально идентифицирующее элемент разрешения
}
```
Поле `name` идентифицирует конкретное имя разрешения. Список интерфейсов системного модуля, соответствующий имени разрешения, выглядит следующим образом:

| Имя разрешения | Соответствующий системный модуль | Описание разрешения |
| ------------------------------------------------ | ------------------------------------------------ | -------------------------------- |
| `watch.permission.FOREGROUND_SERVICE` | [`@system.app`](/api/system-app.md) | Держите приложение работающим на переднем плане |
| `watch.permission.LOCATION` | [`@system.geolocation`](/api/system-geolocation.md) | Информация о местоположении |
| `watch.permission.ACCESS_SENSORS` | [`@system.compass`](/api/system-sensor.md) | Встроенные датчики (например, компас, акселерометр и т. д.) |
| `watch.permission.DEVICE_INFO` | [`@system.device`](/api/system-device.md) | Информация об устройстве |
| `watch.permission.RECORD` | [`@system.media`](/api/system-media.md) | Разрешения требуются только для API, связанных с записью |
| `watch.permission.BLUETOOTH` | [`@system.bluetooth.ble`](/api/system-ble.md) | Разрешить использование устройства Bluetooth |
| `watch.permission.READ_HEALTH_DATA` | Еще не поддерживается | Чтение данных о состоянии здоровья (например, количество шагов, частота сердечных сокращений и т. д.) |
| `watch.permission.SCHEDULE` | [`@system.schedule`](/api/system-schedule.md) | Настройка запланированных задач |
| `watch.permission.NOTIFICATION` | [`@system.notification`](/api/system-notified.md) | Разрешить напоминания об уведомлениях приложений |

#### `router` <decl type="Router" />

Обязательное поле, описывающее информацию о маршрутизации для страниц в приложении. Подробности см. в разделе [`Router` object](#router-object).

#### `display` <decl type="?: Display" />

Подробнее о настройке эффектов отображения в приложении см. в разделе [`Display` object](#display-object).

#### `dial` <decl type="?: Dial" />

Если поле `dial` присутствует, это означает, что этот проект представляет собой пакет набора номера, а не приложение. Конкретные метаданные циферблата описываются [объектом `Dial`](#dial-object). Пакет циферблата [`icon`](#icon) не использует поля.

#### `виджеты` <decl type="?: Widget[]" />

Представляет информацию о конфигурации виджета и списка виджетов. Подробную информацию о полях конфигурации см. в разделе [Объект ``Widget`](#widget-object).

### Объект `Конфигурация`

::: подробности тип подпись
``` тс
Конфигурация интерфейса {
  designWidth?: число,
  designImageScale?: число,
  шрифтFaces?: строка,
  активы?: строка | строка[]
}
```
:::

#### `designWidth` <decl type="?: Number" />

Базовая ширина дизайна страницы в пикселях. Значение по умолчанию — «750». Единица длины «px» в CSS масштабируется на основе отношения фактической ширины устройства к «designWidth». Например, если значение designWidth равно 466, длина пикселя будет масштабироваться в $410/466$ раз на устройстве с фактической шириной 410 пикселей.

Рекомендуется использовать текущий размер устройства вместо размера по умолчанию «750», чтобы избежать большого количества преобразований во время разработки.

#### `designImageScale` <decl type="?: Number" />

Коэффициент масштабирования изображения ресурсов изображения. Значение по умолчанию — $1,0$. Чтобы обеспечить адаптацию разрешения нескольких устройств, дизайнеру необходимо увеличить изображение в соответствии с проектом дизайна, а затем обрезать изображение, чтобы обеспечить качество после упаковки.

`designImageScale` — это соотношение размера исходного изображения ресурса в проекте и логического разрешения масштабированного изображения. В частности, коэффициент масштабирования $\it{scale}$ изображения ресурса на реальном устройстве равен:
$$
\it{scale} = \tt{designImageScale}\frac{\tt{deviceWidth}}{\tt{designWidth}}
$$
Где $\tt{deviceWidth}$ — фактическая ширина экрана устройства. Следовательно, фактический размер отображаемого изображения $(w', h')$ равен:
$$
(w', h') = \it{масштаб} \cdot (w, h)
$$
Где $(w, h)$ — размер исходного изображения ресурса.

::: совет
Не используйте конфигурацию designImageScale меньше $1$. Это означает, что изображение ресурса будет увеличено во время упаковки, что приведет к очевидному размытию и искажению. Если вы хотите, чтобы ваше приложение элегантно отображало изображения на нескольких устройствах, вам следует подготовить изображения ресурсов большего размера, чем требуется, и установить правильный параметр designImageScale.

Например, если размер изображения, отображаемого на реальном устройстве (при условии, что $\tt{designWidth} == \tt{deviceWidth}$) составляет $96\rm px \times 96\rm px$, то вы можете подготовить материал $192\rm px \times 192\rm px$ с удвоенным разрешением и установить для `designImageScale` значение $2$.
:::

#### `fontFaces` <decl type="?: string" />

Укажите путь к файлу таблицы сопоставления шрифтов на уровне приложения, и шрифты, определенные в ней, можно будет использовать непосредственно в приложении. Этот путь может быть относительным к файлу manifest.json или абсолютным относительно корневого каталога пакета ресурсов приложения.

См. [Конфигурация шрифта](font-config.md).

#### `assets` <decl type="?: string | string[]" />

Указывает путь к пользовательскому ресурсу с использованием шаблонов glob (шаблоны файлов). Например:
``` JSON
{
  "конфигурация": {
    "assets": [ "assets/**", "**/data.bin" ]
  }
}
```
Все файлы в каталоге assets в проекте и все файлы data.bin в проекте будут упакованы. Эти файлы будут упакованы только в виде статических файлов ресурсов (то есть файлы будут скопированы напрямую).

Подстановочные знаки файлов могут совпадать с путями, но иметь следующие специальные формы:
- `*` соответствует компоненту пути без разделителя пути (`/`).
- `**` соответствует любому количеству компонентов пути и может включать разделители пути.

Например:
- `test.js` может соответствовать файлам `test.js` в проектах и каталогах.
- `**/*-data.bin` может сопоставлять файлы с суффиксом `-data.bin` по любому пути.
- `*/*.bin` соответствует файлам с суффиксом `.bin` в любом одноуровневом каталоге в корне проекта.

### Объект `Маршрутизатор`

Определите состав страницы и соответствующую информацию о конфигурации.

::: подробности тип подпись
``` тс
интерфейс Маршрутизатор {
  запись?: строка,
  страницы: { [имя: строка]: PageInfo }
}
```
:::

#### `entry` <decl type="?: string" />

Название домашней страницы приложения. На эту страницу будет осуществлен переход после запуска приложения. По умолчанию `"main"`.

#### `pages` <decl type="{ [name: string]: PageInfo }" />

Объявите информацию для каждой страницы. Ключевое слово name атрибутаpages — это имя страницы, а значение атрибута [объект PageInfo](#pageinfo-object) — подробная информация о конфигурации страницы. Например:
``` JSON
{
  "маршрутизатор": {
    "entry": "Основной",
    "страницы": {
      "Основной": {
        "path": "/Путь/К/Основному",
        "компонент": "индекс",
        "launchMode": "singleTask"
      }
    }
  }
}
```

Все страницы приложения должны быть заполнены в таблице маршрутизации, прежде чем их можно будет использовать, и каждая страница также должна иметь уникальное имя.

### Объект `Display`

#### `pageAnimation` <decl type="?: PageAnimation" />

Конфигурация анимации перехода страницы в приложении по умолчанию, значение — [объект PageAnimation](#pageanimation-object).

## Объект `PageInfo`

Объекты конфигурации страницы — это значения свойств объекта router.pages. Тип объекта конфигурации страницы — Объект. В этом разделе представлены определения полей атрибутов объекта конфигурации страницы.

::: подробности тип подпись
``` тс
интерфейс PageInfo {
  путь?: строка,
  компонент?: строка,
  pageAnimation?: PageAnimation,
  launchMode?: «стандартный» | 'singleTask'
}
```
:::

#### `path` <decl type="?: string" />

Путь к каталогу страницы (путь к папке, в которой хранятся компоненты страницы). По умолчанию совпадает с именем страницы, которое является ключом объекта Router.

#### `comment` <decl type="?: string" />

Имя компонента страницы соответствует имени UX-файла и не требует суффикса *.ux*. Например, имя компонента index соответствует файлу index.ux.

#### `pageAnimation` <decl type="?: PageAnimation" />

Конфигурация анимации перехода на странице, значение — [объект PageAnimation](#pageanimation-object). Эта конфигурация имеет приоритет над конфигурацией display.pageAnimation в mainfest.json.

#### `launchMode` <decl type="?: 'standard' | 'singleTask'" version="0.8" />

Режим запуска страницы, по умолчанию — «стандартный». Когда `launchMode` страницы настроен как `singleTask`, если вы хотите открыть экземпляр страницы, который уже находится в стеке возврата, все страницы над экземпляром будут извлечены из стека и возвращены на страницу, где находится экземпляр (аналогично [`router.back('<page-name>')`](/api/system-router.md#back)) вместо создания нового экземпляра страницы.

При «открытии» в режиме «singleTask» и возврате на уже существующую страницу срабатывает функция жизненного цикла [`onRefresh`](../comComponent/life-cycle.md#onrefresh).

### Объект `PageAnimation`

Свойства этого объекта настраивают поведение анимации перехода страниц. Анимация перехода эффективна только для верхней страницы, анимация перехода не будет воспроизводиться на неверхних страницах.

::: подробности тип подпись
``` тс
интерфейс PageAnimation {
  openEnter?: строка,
  closeEnter?: строка,
  openExit?: строка,
  closeExit?: строка
}
```
:::

Каждый атрибут может принимать следующие значения:
- `"none"`: нет анимации перехода, это значение по умолчанию для всех свойств.
- `"slide"`: переход страницы осуществляется с помощью анимации скольжения. Этот эффект перехода варьируется в зависимости от различных свойств конфигурации перехода, в том числе:
  - Для перехода `openEnter` эффект слайда заключается в том, что страница начинается слева направо до тех пор, пока полностью не закроет экран.
  - Для перехода closeExit эффект слайда заключается в том, что страница начинает с полного закрытия экрана и скользит вправо, пока полностью не покинет экран.
  - Для переходов closeEnter и openExit эффект слайда не анимируется.

Анимация перехода по умолчанию для страниц и приложений определяется устройством. Если поля, связанные с pageAnimation, не указаны в manifest.json, некоторые устройства могут не воспроизводить анимацию перехода, в то время как другие устройства могут использовать эффекты анимации, настроенные производителем.

::: предупреждение
Эмулятор всегда будет воспроизводить анимацию перехода страницы слайда, независимо от того, какое устройство он эмулирует. Если вы хотите убедиться, что анимация перехода страниц отключена, используйте
``` JSON
{
  "pageAnimation": { "openEnter": "none" }
}
```
Этот способ записи не является `"pageAnimation": {}`, который не действует по неизвестным причинам.
:::

#### `openEnter` <decl type="?: string" />

Это свойство настраивает анимацию перехода новой страницы при открытии новой страницы.

#### `closeEnter` <decl type="?: string" />

Это свойство настраивает анимацию перехода старой страницы, которая будет перезаписана при открытии новой страницы.

#### `openExit` <decl type="?: string" />

Это свойство настраивает анимацию перехода закрытия закрытой страницы при ее закрытии.

#### `closeExit` <decl type="?: string" />

Это свойство настраивает анимацию перехода страницы, которая будет повторно отображаться под закрытой страницей, когда страница закрыта.

### Объект `Dial`

Объект `Dial` описывает информацию о конфигурации, связанную с набором номера.

::: подробности тип подпись
``` тс
интерфейс Dial {
  компонент: строка,
  предварительный просмотр: строка
}
```
:::


#### `компонент` <decl type="string" />

Путь к компоненту записи циферблата. Может быть абсолютным путем внутри пакета или относительно файла manifest.json.

#### `предварительный просмотр` <decl type="string" />

Путь к изображению предварительного просмотра циферблата. Может быть абсолютным путем внутри пакета или относительно файла manifest.json.

### Объект `Виджет`

Объект «Виджет» описывает информацию о конфигурации виджета или виджета.

::: details 类型签名
``` ts
interface Widget {
  name: string,
  component: string,
  preview: string
}
```
:::

#### `name` <decl type="string" />

挂件/小部件的名字，同一个应用包内的小部件不能重名。

#### `component` <decl type="string" />

挂件/小部件入口组件的路径。可以是包中的绝对路径或相对于 `manifest.json` 文件的相对路径。

#### `preview` <decl type="string" />

挂件/小部件预览图片的路径。可以是包中的绝对路径或相对于 `manifest.json` 文件的相对路径。
