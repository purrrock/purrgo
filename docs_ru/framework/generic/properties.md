# Свойства и события

В этом разделе представлены общие интерфейсы свойств и события, предоставляемые всеми собственными компонентами.

## Список свойств

### Общие свойства

#### `top` <decl type="number" get set Listen />

Положение верхней части компонента относительно родительского собственного компонента в пикселях. Этот атрибут на самом деле является аббревиатурой атрибута top во встроенных стилях. Дополнительные сведения о том, как его использовать, см. в разделе [Операция позиционирования компонента](#Операция позиционирования компонента).

При чтении или прослушивании свойства `top` будет получено расчетное положение компонента, а также фактическое измеренное значение после компоновки.

#### `left` <decl type="number" get set Listen />

Положение левой части компонента относительно родительского собственного компонента в пикселях. Этот атрибут на самом деле является аббревиатурой атрибута left во встроенных стилях. Дополнительные сведения о том, как его использовать, см. в разделе [Операция позиционирования компонента](#Операция позиционирования компонента).

При чтении или прослушивании свойства left будет получено расчетное положение компонента, а также фактическое измеренное значение после компоновки.

#### `width` <decl type="number" get set Listen />

Ширина компонента. Когда свойство width установлено, свойство [width](styles.md#width) во встроенном стиле обновляется. Поскольку ширина CSS принимает режим рамки, фактическое сохраненное значение стиля будет автоматически добавлено к текущим размерам «отступа» и «границы» элемента, тем самым гарантируя, что ширина содержимого после макета соответствует установленному значению.

При чтении или прослушивании атрибута width вы получите рассчитанную ширину содержимого макета, исключая отступы и границы.

#### `height` <decl type="number" get set Listen />

Высота компонента. Когда свойство Height установлено, свойство [height](styles.md#height) во встроенном стиле обновляется. Поскольку высота CSS принимает режим рамки, фактическое сохраненное значение стиля будет автоматически добавлено к текущим размерам «отступа» и «границы» элемента, тем самым гарантируя, что высота содержимого после макета соответствует установленному значению.

При чтении или прослушивании атрибута «height» вы получите высоту содержимого, рассчитанную по макету, без учета «отступов» и «границы».

#### `show` <decl type="boolean" get set/>

Установите, будет ли компонент виден. Скрытые компоненты не отображаются и не занимают пространство макета.

#### `quiescent` <decl type="boolean" get set/>

Установите, будут ли снимки компонентов обновляться автоматически (статичные снимки). Если компонент отображается через снимок, а значение этого свойства равно «false» (значение по умолчанию), снимок будет обновлен немедленно, чтобы обновить представление при обновлении содержимого компонента, в противном случае снимок не будет обновлен немедленно. Установка для этого свойства значения true может повысить производительность пользовательского интерфейса, но приведет к задержке отображения содержимого.

В следующем примере показан атрибут «quiescent» в действии. В интерфейсе есть два элемента `p`, помещенные в контейнер `scroll`, и для контейнера `scroll` включен [режим моментального снимка](../../comComponents/scroll.md#snapshot). Когда пользователь прокручивает компонент «прокрутка», будет сделан снимок элементов в нем. Поскольку первый элемент p находится в обычном режиме снимка, а второй элемент p — в режиме статического снимка, при прокрутке обновляется только содержимое первого элемента p.

<glyphix id="generic-properties-quiescent" height="200" title="Ленивый снимок">

``` HTML
<снимок прокрутки Scroll-snap="center">
  <p>обычный снимок {{ count }}</p>
  <p quiescent>Снимок состояния покоя {{ count }}</p>
</прокрутка>
```

``` CSS
прокрутить {
  дисплей: гибкий;
  гибкое направление: столбец;
  цвет фона: светло-серый;
}

п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
  отступ: 10 пикселей;
  поле: 10 пикселей;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    количество: 0
  },
  onReady (событие) {
    setInterval(() => this.count++, 500)
  }
}
```

</глификс>

#### `style` <decl type="string" set />

Установите встроенный стиль компонента. В настоящее время поддерживается только [свойство CSS](./styles.md) с тегом <badge type="info" text="inline" />.

#### `z-index` <decl type="number" get set />

Атрибут z-index задает порядок элементов по оси Z, причем перекрывающиеся элементы с большим индексом z охватывают меньшие элементы. Значение этого свойства будет переопределено свойством [`z-index`](styles.md/#z-index) в CSS.


#### `opacity` <decl type="number" get set />

Указывает прозрачность компонента, диапазон значений — $[0, 1]$, где $0$ означает полную прозрачность. Имеет тот же эффект, что и свойство CSS [`opacity`](styles.md#opacity).

::: предупреждение
Значение непрозрачности повлияет на производительность отрисовки элемента. Подробную информацию см. в описании CSS-свойства [`opacity`](styles.md#opacity).
:::

#### `transform` <decl type="string" set />

Установите преобразование компонента, которое эквивалентно свойству CSS [`transform`](styles.md#transform).

#### `disabled` <decl type="boolean" get set />

Используется для установки или получения отключенного состояния компонента. Если значение атрибута равно true, элемент отключен, пользователь не может с ним взаимодействовать, и элемент не будет реагировать ни на какие жесты (например, щелчки, перетаскивания и т. д.). Если значение свойства равно false (значение **по умолчанию**), компонент находится в пригодном к использованию состоянии и пользователи могут взаимодействовать с ним обычным образом.

В следующем примере показано использование атрибута `disabled`, а также управление стилем с помощью псевдокласса CSS [`:disabled`](styles.md#disabled). Этот пример показывает, что элемент div может реагировать на жесты щелчка в обычном состоянии, но не реагирует ни на какие жесты в состоянии «отключено».

<glyphix id="generic-properties-disabled" height="200" title="отключенные свойства">

``` HTML
<div :disabled="disabled" on:click="onClick">
  {{отключено? 'отключено': 'нормально'}} <switch />
</div>
```

``` CSS
дел {
  цвет фона: светло-серый;
  выравнивание текста: по центру;
  дисплей: гибкий;
  оправдание-содержание: центр;
}

/* Псевдокласс :disabled может управлять стилем элементов в отключенном состоянии */
div: отключено {
  непрозрачность: 0,5;
}
```

``` js
импортировать приглашение из @system.prompt

экспортировать по умолчанию {
  данные: {
    отключено: ложь
  },
  onInit() {
    setInterval(() => {
      это.отключено = !это.отключено
    }, 2000)
  },
  onClick() {
    Prompt.showToast({ сообщение: 'нажато!', продолжительность: 250 })
  }
}
```

</глификс>

### Общие события

Большинство собственных компонентов поддерживают общие события, которые можно прослушивать с помощью [директивы `on`](../commands/on.md). Типы значений этих событий описаны в разделе [EventTypes](#EventTypes).

#### `touchstart` <decl type="TouchEvent" Listen />

Событие touchstart вызывается, когда пользователь начинает прикасаться к компоненту. Значения событий имеют тип [`TouchEvent`](#touchevent).

#### `touchmove` <decl type="TouchEvent" Listen />

Событие touchmove запускается, когда точка касания пользователя перемещается по компоненту. Во время перемещения это событие будет срабатывать всегда, даже если точка касания выходит за пределы текущего нативного компонента. Значения событий имеют тип [`TouchEvent`](#touchevent).

Существует определенная «мертвая зона движения», когда состояние касания переходит от «touchstart» к «touchmove». Если расстояние скольжения касания пользователя меньше диапазона мертвой зоны, «touchmove» не сработает. Диапазон мертвой зоны движения варьируется от устройства к устройству. В следующем примере показана мертвая зона движения.

<glyphix id="generic-properties-touchmove" height="200" title="Переместить мертвую зону">

``` HTML
<p on:touchstart="state = 'start'"
   on:touchmove="onTouchMove($event)"
   on:touchend="onTouchEnd">
  {{ `state: ${state} \ndead area: (${dx}, ${dy})` }}
</p>
```

``` CSS
п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    состояние: ноль,
    дх: ноль,
    ды: ноль
  },
  onTouchMove (событие) {
    if (!this.dx && !this.dy) {
      this.state = 'переместить'
      this.dx = event.touches[0].offsetX
      this.dy = event.touches[0].offsetY
    }
  },
  onTouchEnd() {
    this.state = 'конец'
    this.dx = this.dy = ноль
  }
}
```

</глификс>

#### `touchend` <decl type="TouchEvent" Listen />

Когда пользователь касается экрана, событие touchend отправляется на родной компонент, к которому он ранее прикасался. Значения событий имеют тип [`TouchEvent`](#touchevent).

#### `touchcancel` <decl type="TouchEvent" Listen />

`touchcancel` срабатывает, когда касание собственного компонента прерывается. Значения событий имеют тип [`TouchEvent`](#touchevent). Существует множество причин, по которым касание может быть прервано, например, скрытие компонента или необходимость реагирования на событие касания другими элементами.

#### `click` <decl type="ClickEvent" Listen />

Событие «click» запускается, когда нативный компонент щелкается и отпускается. Значения событий имеют тип [`ClickEvent`](#clickevent).

<glyphix id="generic-properties-click" height="100">

``` HTML
<p on:click="click = JSON.stringify($event)">
  {{ нажмите }}
</p>
```

``` CSS
п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    клик: ноль
  }
}
```

</глификс>

#### `longpress` <decl type="LongPressEvent" Listen />

Событие longpress срабатывает, когда нативный компонент нажимается в течение длительного времени. Значения событий имеют тип [`LongPressEvent`](#longpressevent). Следующий интерактивный пример показывает, когда запускаются «longpress» и другие события:

<glyphix id="generic-properties-longpress" height="100">

``` HTML
<p on:touchstart="state = 'касаюсь...'"
   on:longpress="state = `longpress: ${JSON.stringify($event)}`"
   on:click="state = 'нажал.'">
  {{ состояние }}
</p>
```

``` CSS
п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    состояние: ноль
  }
}
```

</глификс>

Время срабатывания и продолжительность события «longpress» варьируются от устройства к устройству, обычно после нажатия $500 \rm ms$. В отличие от события [`click`](#click), `longpress` срабатывает во время нажатия, а не при отпускании руки. В приведенном выше примере вы найдете:
- Когда время нажатия меньше времени срабатывания длительного нажатия, событие «щелчок» будет вызвано после отпускания;
- Событие «longpress» будет запускаться при достаточно длительном нажатии, а событие «click» будет запускаться при отпускании (отображается как статус «clicked»);
- Движение во время нажатия не вызывает события «длительное нажатие» или «щелчок».

#### `swipe` <decl type="SwipeEvent" Listen />

Событие `swipe` вызывается при быстром пролистывании компонента. Значения событий имеют тип [`SwipeEvent`](#swipeevent).

<glyphix id="generic-properties-swipe" height="250" >

``` HTML
<p on:swipe="onSwipe($event)">
  {{ проведите пальцем }}
</p>
```

``` CSS
п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    проведите пальцем по экрану: ноль
  },
  onSwipe (событие) {
    this.swipe = event.direction
    событие.strongResponse()
  }
}
```

</глификс>

#### `keydown` <decl type="KeyEvent" Listen />

Это событие вызывается при нажатии клавиши. События `keydown` и `keyup` используются для захвата операций нажатия клавиш объекта. Для захвата событий нативный компонент должен быть в фокусе. Корневой элемент страницы всегда получает фокус автоматически, поэтому следующий код может перехватывать события `keydown` и `keyup`:
``` HTML
<!-- Предполагается, что это корневой элемент страницы -->
<div on:keydown="console.log($event)" on:keyup="console.log($event)">
  ...
</div>
```
Тип значения события см. в [`KeyEvent`](#keyevent).

Устройства часов обычно регистрируют [обработчик клавиш по умолчанию](/api/system-internal.md#setdefaultkeyhandler), чтобы код приложения мог взаимодействовать, не реагируя на такие события (например, некоторые часы возвращаются на предыдущую страницу при нажатии клавиши питания). Чтобы предотвратить ответ клавиши по умолчанию, используйте метод stopPropagation() объекта KeyEvent, чтобы предотвратить всплывание.

#### `keyup` <decl type="KeyEvent" Listen />

Это событие вызывается при нажатии кнопки. Для получения дополнительной информации обратитесь к событию [`keydown`](#keydown).

#### `wheel` <decl type="WheelEvent" Listen />

Событие «wheel» запускается, когда пользователь вращает колесо. Устройства с колесом прокрутки включают вращающуюся заводную головку часов или колесо мыши. Чтобы запечатлеть это время, нативный компонент должен быть в фокусе. Корневой элемент страницы всегда получает фокус автоматически, поэтому следующий код может перехватить событие «колесо»:
``` HTML
<!-- Предполагается, что это корневой элемент страницы -->
<div on:wheel="console.log($event)">
  ...
</div>
```
Тип значения события см. в [`WheelEvent`](#wheelevent).

## Тип события

### `BaseEvent`

Объект события BaseEvent предоставляет некоторые методы для управления доставкой событий. Его прототип:
``` тс
интерфейс BaseEvent {
  StrongResponse(): void, // Принудительно реагировать на события
  stopPropagation(): void // Остановить всплывание событий
}
```

### `TouchEvent`

Прототип объекта события TouchEvent:
``` тс
интерфейс TouchEvent расширяет BaseEvent {
  isTarget: boolean, // Является ли цель события текущим компонентом
  touches: { // Все данные о точках касания этого события
    clientX: число, // Координата X точки касания относительно области содержимого целевого компонента
    clientY: число, // координата y точки касания относительно области содержимого целевого компонента
    offsetX: число, // Смещение точки касания в направлении x во время процесса касания
    offsetY: число // Смещение точки касания в направлении y во время процесса касания
  }[];
}
```

### `ClickEvent`

Прототип объекта события SwipeEvent:
``` тс
интерфейс SwiperEvent расширяет BaseEvent {
  isTarget: boolean, // Является ли цель события текущим компонентом
  clientX: число, // координата x точки касания щелчка относительно области содержимого целевого компонента.
  clientY: число // Координата Y точки касания щелчка относительно области содержимого целевого компонента.
}
```

### `LongPressEvent`

Прототип объекта события LongPressEvent:
``` тс
интерфейс SwiperEvent расширяет BaseEvent {
  isTarget: boolean, // Является ли цель события текущим компонентом
  clientX: число, // координата X точки касания при длительном нажатии относительно области содержимого целевого компонента.
  clientY: число // Координата Y точки касания при длительном нажатии относительно области содержимого целевого компонента.
}
```

### `SwipeEvent`

Прототип объекта события SwipeEvent:
``` тс
интерфейс SwiperEvent расширяет BaseEvent {
  isTarget: boolean, // Является ли цель события текущим компонентом
  направление: «налево» | 'право' | 'вверх' | 'вниз' // направление развертки
}
```

### `KeyEvent`

Объект KeyEvent описывает событие взаимодействия пользователя с ключом сущности. Этот тип используется для атрибутов событий элементов [`keydown`](#keydown) и [`keyup`](#keyup). Прототип объекта события KeyEvent:
``` тс
интерфейс KeyEvent {
  введите: «нажатие клавиши» | 'keyup', // Тип ключевого события
  ключ: строка, // имя ключа
  timestamp: число, // временная метка отчета о ключевых событиях, единица измерения — миллисекунды
  stopPropagation(): void // Вызовите этот метод, чтобы предотвратить всплытие событий
}
```

В настоящее время поддерживаются следующие имена ключей:
- «Питание»: кнопка питания часов;
- `'Fn'`: функциональная клавиша часов;
- Другие печатаемые символьные клавиши используют один символ для формирования имени клавиши, например букву «А», знак минус «-» и т. д.

### `WheelEvent`

Объект WheelEvent описывает событие взаимодействия с пользователем для вращения колеса. Этот тип используется для атрибута события элемента [`wheel`](#wheel). Сигнатура объекта события WheelEvent:
``` тс
интерфейс WheelEvent {
  deltaY: число, // Приращение колеса в направлении y
  stopPropagation(): void // Вызовите этот метод, чтобы предотвратить всплытие событий
}
```

В отличие от события колеса в Интернете, WheelEvent в Glyphix в настоящее время содержит только атрибут deltaY.

## Механизм реагирования на события

### Всплывание событий

События касания и жеста поддерживают всплывание. Всплытие означает, что когда событие происходит в элементе, оно сначала выполняет обработчик этого элемента, затем обработчик его родительского элемента, а затем вплоть до обработчиков других предков. В приведенном ниже примере зеленый компонент «p» и серый компонент «div» прослушивают события касания. При нажатии на компонент «p» будет видно, что как компонент «p», так и компонент «div» могут получить событие.

<glyphix id="generic-event-bubbling" height="250" title="Всплывание событий касания">

``` HTML
<div on:touchstart="onTouch('div', $event)"
     on:touchmove="onTouch('div', $event)"
     on:touchend="onRelease('div', $event)">
  <p on:touchstart="onTouch('p', $event)"
     on:touchmove="onTouch('p', $event)"
     on:touchend="onRelease('p', $event)">
    {{ `касается: ${touchs.div ? 'div': '-'} ${touchs.p ? 'p': '-'}, цель: ${target}` }}
  </p>
</div>
```

``` CSS
дел {
  дисплей: гибкий;
  гибкое направление: столбец;
  цвет фона: светло-серый;
  оправдание-содержание: пространство вокруг;
}

п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
  высота: 150 пикселей;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    касается: { div: false, p: false },
    цель: ноль
  },
  onTouch (имя, событие) {
    this.touchs[имя] = правда
    // Атрибут isTarget может определить, является ли целью события компонент, который в данный момент прослушивает событие
    если (event.isTarget)
      this.target = имя
  },
  onRelease (имя, событие) {
    this.touchs[имя] = ложь
    если (event.isTarget)
      this.target = ноль
  }
}
```

</глификс>

В Glyphix в этом документе всплывают только события касания и жеста. Перехват событий в настоящее время невозможен в коде JavaScript.

### Предотвращение всплытия событий

Используйте метод stopPropagation() класса BaseEvent, чтобы предотвратить передачу событий родительскому элементу.

### Событие сильной реакции

В Glyphix есть два приоритета реагирования на события прикосновения или жеста: сильный ответ и слабый ответ. Когда событие имеет несколько целей, на которые необходимо реагировать одновременно, сильные реакции имеют более высокий приоритет, чем слабые. Предположим, что в интерфейсе есть 3 уровня родительско-дочерних элементов: `A -> B -> C`, где `C` слабо реагирует на события, а `B` сильно реагирует, тогда событие будет отправлено в `B`, а затем не в `C`. Элемент, который изначально сильно отреагировал на событие, повторно отправит событие после перехода на слабый ответ.

События касаний и жестов в [Универсальные события](#Универсальные события) по умолчанию реагируют слабо. В приведенном ниже примере зеленый компонент «p» размещается внутри серого «прокрутки» и прослушивает все события касания компонента «p». Поскольку «прокрутка» по умолчанию сильно реагирует на жесты скольжения вверх и вниз, слабо реагирует на жесты скольжения влево и вправо и не реагирует на другие жесты, во время работы можно наблюдать:
- Событие touchstart будет вызвано при нажатии компонента p, а событие touchend будет запущено при отпускании компонента p;
— Событие touchmove будет вызвано при перетаскивании компонента p по горизонтали;
- При перетаскивании компонента `p` вверх и вниз, поскольку родительский компонент `scroll` сильно реагирует на скольжение вверх и вниз, в то время как компонент `p` в коде шаблона слабо реагирует на `touchmove`, на скольжение вверх и вниз будет реагировать компонент `scroll`, а компонент `p` получит событие `touchcancel`.

<glyphix id="generic-event-strong-response-1" height="250" title="Событие сильной реакции">

``` HTML
<прокрутка>
  <p on:touchstart="state = 'touchstart'"
     on:touchmove="state = 'touchmove'"
     on:touchend="state = 'touchend'"
     on:touchcancel="state = 'touchcancel'">
    {{ `p.state: ${state}` }}
  </p>
</прокрутка>
```

``` CSS
прокрутить {
  цвет фона: светло-серый;
}

п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
  высота: 150 пикселей;
  поле: 50 пикселей;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    состояние: ноль
  }
}
```

</глификс>

Механизм обработки событий жестов по умолчанию во многих собственных компонентах очень отзывчив. Вы можете указать событие в коде JavaScript, чтобы оно находилось в режиме строгого ответа, используя метод `strongResponse()` объекта `BaseEvent`. В приведенном ниже примере внешний серый компонент div будет сильно реагировать на жесты, поэтому даже если коснуться внутреннего элемента p, событие будет отправлено элементу div только после начала жеста.

<glyphix id="generic-event-strong-response-2" height="250" title="Событие сильной реакции">

``` HTML
<div on:touchstart="onTouch('div', 'start', $event)"
     on:touchmove="onTouch('div', 'move', $event)"
     on:touchend="onTouch('div', 'end', $event)"
     on:touchcancel="onTouch('div', 'cancel', $event)">
  <p on:touchstart="onTouch('p', 'start', $event)"
     on:touchmove="onTouch('p', 'move', $event)"
     on:touchend="onTouch('p', 'end', $event)"
     on:touchcancel="onTouch('p', 'cancel', $event)">
    {{ `состояние div: ${touchs.div}, состояние p: ${touchs.p}, цель: ${target}` }}
  </p>
</div>
```

``` CSS
дел {
  дисплей: гибкий;
  гибкое направление: столбец;
  цвет фона: светло-серый;
  оправдание-содержание: пространство вокруг;
}

п {
  цвет фона: светло-зеленый;
  выравнивание текста: по центру;
  высота: 150 пикселей;
}
```

``` js
экспортировать по умолчанию {
  данные: {
    касается: { div: null, p: null },
    цель: ноль
  },
  onTouch (имя, состояние, событие) {
    console.log(имя, состояние, event.isTarget)
    this.touchs[имя] = состояние
    // Атрибут isTarget может определить, является ли целью события компонент, который в данный момент прослушивает событие.
    // Если это событие отмены, цель не будет записана.
    if (event.isTarget && состояние != 'отмена')
      this.target = имя
    если (имя == 'div')
      событие.strongResponse()
  }
}
```

</глификс>

### Обработка событий страницы по умолчанию

По умолчанию страница будет слабо реагировать на события жестов и предотвращать всплеск событий, поэтому события жестов не могут быть отправлены и доставлены через страницу. Кроме того, страница закроется при получении правого жеста касания. Разработчики также могут перехватить жест, чтобы отключить эту функцию.

Конкретный метод заключается в прослушивании жеста touchmove компонента страницы и предотвращении всплытия:
``` HTML
<!-- Этот элемент div является корневым компонентом страницы -->
<div on:touchmove="$event.stopPropagation()">
  ...
</div>
```
Таким образом, эту страницу нельзя вернуть, проведя пальцем вправо, но ее можно вернуть, нажав физическую клавишу питания. Чтобы запретить пользователю сначала нажимать клавиши, вы можете использовать следующее:
``` HTML
<!-- Этот элемент div является корневым компонентом страницы -->
<div on:keydown="onKeyup">
  ...
</div>
```

``` js
экспортировать по умолчанию {
  onKeyup (событие) {
    // Отключить всплывание событий, когда значение ключа равно «Power», чтобы предотвратить выход со страницы
    если (event.key == 'Питание')
      событие.stopPropagation()
  }
}
```

::: предупреждение
Тщательно замените механизм обработки событий страницы по умолчанию, чтобы избежать ситуации, когда пользователь не сможет вернуться на страницу.
:::

::: совет
В предыдущих версиях событие жеста `swipe` использовалось для предотвращения возврата страницы по умолчанию, но в версии 0.6.4 от этого метода отказались. Вместо этого используйте обработчик событий touchmove, указанный выше. Эта корректировка вызвана тем, что интерактивная анимация возврата страницы (т. е. последующий выход) совершенно несовместима с семантикой «пролистывания», которая предотвращает возврат страницы.
:::

## Советы по использованию

### Операция положения компонента

Положение компонента можно легко изменить, используя свойства `top` и `left` собственных компонентов:
``` HTML
<div :top="40" :left="20"> ... </div>
```
`top` и `left` на самом деле являются сокращением одноименных свойств CSS, поэтому они будут действовать только в абсолютных макетах, чего можно добиться с помощью следующего CSS:
``` CSS
дел {
  позиция: абсолютная;
}
```

Затем вы можете использовать адаптивные свойства для изменения положения компонента. В следующем примере показано анимированное случайное перемещение положения компонента, достигнутое в сочетании с модификатором [`transition`](/framework/comComponent/prop-modifier.md#transition-modifier).

<glyphix id="generic-widget-position" height="250" title="Случайное положение компонента">

``` HTML
<div id="панель">
  <p id="tile" :top="top" :left="left"
     верхний.переход левый.переход>
    Плитка
  </p>
</div>
```

``` CSS
дел {
  цвет фона: светло-серый;
}

p {
  /* 要使用组件的 top / left 属性就必须是绝对定位 */
  position: absolute;
  background-color: lightgreen;
  text-align: center;
  width: 3rem;
  height: 3rem;
  border: 4px solid red;
  border-radius: 10%;
}
```

``` js
export default {
  data: {
    top: 0,
    left: 0
  },
  timer: null,
  onReady() {
    // 获取组件对象，位置范围不应超出 #pane 容器
    const pane = this.$element("pane")
    const tile = this.$element("tile")
    const width = pane.width - tile.width
    const height = pane.height - tile.height
    this.timer = setInterval(() => {
      this.top = Math.random() * height
      this.left = Math.random() * width
    }, 2000)
  },
  onDestroy() {
    clearInterval(this.timer)
  }
}
```

</glyphix>

本示例每隔两秒钟随机设置一次 `#tile` 组件的位置，且范围不超出容器 `#pane` 的边界。默认的 `transition` 修饰符会播放 $1$ 秒钟的过渡动画。
