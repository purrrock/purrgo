#для директивы

Директива for используется для рендеринга списка.

## Синтаксис

``` HTML
<div for="expr"></div> <!-- Не определять индексы и переменные итерации -->
<div for="value in expr"></div> <!-- Не определять переменные индекса -->
<div for="index, значение в выражении"></div>
<div for="(индекс, значение) в выражении"></div>
```
Значение, выраженное выражением `expr`, представляет собой [объект Array`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array) или числовое значение. Инструкция for обходит весь список и передает значение индекса и значение элемента итерации во время процесса итерации. Если вы не определяете переменную индекса или переменную итерации, имя по умолчанию — `$idx` для индексной переменной и `$item` для переменной итерации.

Когда директивы for и if существуют одновременно, директива if имеет более высокий приоритет. Это означает, что если директива if принимает значение false, весь список не будет отображен.

Значение атрибута директивы for поддерживает синтаксис [Значение атрибута директивы](/framework/comComponent/template.md#Значение атрибута директивы), поэтому для заключения выражений также можно использовать двойные фигурные скобки.

::: предупреждение
Не рекомендуется использовать директивы if и for вместе, чтобы улучшить читаемость кода.
:::

## Отображение списка

Отобразите [массив JavaScript](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/First_steps/Arrays) в виде списка с помощью директивы for. Обычно он используется для дочерних компонентов [`scroll`](/comComponents/scroll.md), например:
``` HTML
<прокрутка :damping="демпфирование">
  <p for="item in items" class="item">
    {{ элемент.сообщение }}
  </p>
</прокрутка>
```
Директива for для компонента p выполняет итерацию по массиву item и генерирует узел компонента p для каждого итерируемого элемента. `item` — это имя переменной повторяемого элемента, а доступ к его свойству `message` осуществляется в `{{ item.message }}` [выражение интерполяции](/framework/comComponent/template.md#Interpolation Expression).

`items` — это [свойство объекта компонента](/framework/comComponent/comComponent-object.md) типа массива, например:
``` js
экспортировать по умолчанию {
  данные: {
    предметы: [
      {сообщение: 'Фу' },
      {сообщение: 'Бар' },
      {сообщение: 'Баз' },
    ]
  }
}
```

Вы также можете использовать имя переменной итерации `$item` по умолчанию:
``` HTML

    {{ $item.message }}
  </p>
</прокрутка>
```
Результат рендеринга такой же, как указано выше.

## Вложенность и область видимости

В том же теге индексы и переменные итерации должны быть доступны после директивы for, поэтому вам необходимо обратить внимание на порядок связанных атрибутов:
``` HTML
<panel for="value in expr" title="value.title"></panel> <!-- Правильно -->
<panel title="value.title" for="value in expr"></panel> <!-- Ошибка -->
```
Неправильный порядок не приведет к ошибке компиляции, но будет попытка найти атрибут value в области this. Другими словами, переменные, определенные в директиве for, скрывают имена внешней области, в том числе:
- Модель представления компонента (т. е. доступ к ней осуществляется через свойство this).
- глобальные объекты

Учитывая проблемы области видимости переменных и приоритета директив, директива if должна предшествовать директиве for, иначе может возникнуть путаница.

Для текущего узла компонента переменные, определенные в директиве for, видны только в свойствах после него. Также отображается в статических подкомпонентах, например.
``` HTML
<panel for="значение в выражении" title="value.title">
  <p>сообщение: {{value.message}}</p>
</панель>
<p>{{value.message}}</p> <!-- Посетите this.value.message в это время -->
```
За исключением последнего выражения `{{value.message}}`, несколько других `value` входят в область действия директивы `for`.

Директива for может быть вложенной, а правила области действия такие же, как указано выше. Обратите внимание, что область действия переменных индекса и итерации с одинаковыми именами будет скрыта внутренней директивой for, поэтому эти переменные необходимо определить явно.

## Обнаружение изменения массива

Директива `for` может обнаруживать изменения в массиве [Response](/framework/comComponent/comComponent-object.md#Response Programming) и обновлять интерфейс. Следующие операции вызовут обновления рендеринга for:
- Заменить массив на новый;
- Вызовите метод обновления массива, например [`push()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Array/push), [`pop()`](https://developer.mozilla.org/docs/Web/Ja javaScript/Reference/Global_Objects/Array/pop), [`shift()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Array/shift), [`unshift()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Array/unshift), [`splice()`](https://developer.mozilla.org/docs/W eb/JavaScript/Reference/Global_Objects/Array/splice), [`sort()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Array/sort) и [`reverse()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Array/reverse).

### Заменить массив

Реактивное свойство, используемое для отрисовки списка, можно заменить новым массивом для запуска обновлений пользовательского интерфейса. Например:
``` js
this.items = this.items.filter((item) => item.message.match(/Foo/))
```
Таким образом, `this.items` присваивается новому массиву, и директива `for` повторно отобразит новый список после этой операции.

::: совет
Массивы имеют некоторые неизменяемые методы, такие как filter(), concat() и Slice(), которые не меняют исходный массив, но всегда возвращают новый массив. При обнаружении неизменяемых методов вам необходимо использовать описанный выше метод, чтобы заменить старый массив новым.
:::

### Метод обновления массива

Обновления представления также можно запускать с помощью метода обновления массива, например:
``` js
//Вставляем новый элемент с содержимым Gault внизу исходного списка
this.items.push({ сообщение: 'Гролт' })
```

Вы также можете напрямую изменить длину массива, чтобы усечь его, например:
``` js
// Удаляем элементы после третьего элемента в списке
this.items.length = 2
```

Вы также можете изменить элементы списка:
``` js
//Изменяем содержимое второго элемента на Gault
this.items[1] = { сообщение: 'Гролт' }
```

::: предупреждение
Команда for в настоящее время не может отслеживать изменения атрибутов элементов списка. Подробности см. в разделе [Обновление элемента списка](#Обновление элемента списка).
:::

## Дефекты и ограничения

### Обновление элемента списка

Директива for не может прослушивать глубокие обновления свойств элементов массива.
``` js
this.items[1].message = 'Гральт'
```
Обновления интерфейса не будут запускаться корректно. Чтобы решить эту проблему, элемент массива необходимо заменить новым объектом:
``` js
this.items[1] = { сообщение: 'Гролт' }
```

Если объект проекта имеет много атрибутов, но требуется обновить только некоторые из них, рекомендуется использовать [развернуть синтаксис (`...`)](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Operators/Spread_syntax), чтобы скопировать объект, а затем обновить атрибуты:
``` js
this.items[1] = {
  ...this.items[1], // Копируем все атрибуты второго элемента
  message: 'Gault' // Обновить свойство сообщения
}
```

::: предупреждение
Количество атрибутов объекта элемента массива будет влиять на производительность. Если вы обнаружите, что обновление списка зависло, обратитесь к разделу [Ненужные обновления](#Ненужные обновления).

По таким причинам, как другие элементы интерфейса, которые обновляются вместе, интерфейс может быть обновлен после непосредственного изменения глубоких свойств проекта, но это не стабильно, пожалуйста, не используйте его таким образом.
:::

### Проблема с индексом списка

Хотя директива for поддерживает получение индекса элемента во время рендеринга, например:
``` HTML
<p for="индекс, значение в элементах">
  {{ индекс }} – {{ значение }}
</p>
```
Однако оперативное обновление индексов в настоящее время не поддерживается, а изменения в массиве item могут привести к путанице при отображении. Обновление всего массива позволяет избежать этой проблемы.

Однако из-за некоторых механизмов оптимизации разработчикам сложно гарантировать фактическое обновление всего массива `items`, что может привести к странной и неожиданной путанице индексов.

### Ненужные обновления

Отображение списков может быть одним из узких мест для плавности и производительности, особенно длинных списков, отображение которых может происходить медленнее. Сокращение ненужных обновлений списков может быть эффективным методом оптимизации.

#### Обновите список напрямую

Рассмотрим такой список:
``` HTML
<div for="(idx, задача) в задачах" on:click="process(idx)">
  <p>{{ Task.name }}</p>
  <p>{{ Task.progress }}%</p>
</div>
```
Это интерфейс обработки задач, который отображает список задач и обрабатывает задачу, когда пользователь нажимает на нее. Для простоты мы инициализируем список задач следующим образом:
``` js
this.tasks = Array.from({ length: 10 },
  (_, i) => ({ name: `Task #${i + 1}`, прогресс: 0 }))
```
На этом этапе вы увидите список дел из 10 пунктов. Следующий методprocess() просто обновляет ход выполнения задачи:
``` js
процесс(idx) { // idx — это индекс выбранного элемента задачи
  this.tasks[idx].progress = 0
  //Создаем таймер для имитации процесса обработки
  let timer = setInterval(() => {
    // Поскольку инструкция for не поддерживает глубокие обновления атрибутов, сначала скопируйте объект
    пусть задача = {...this.tasks[idx]}
    задача.прогресс += 10
    this.tasks[idx] = задача
    если (task.progress >= 100)
      ClearInterval(timer) //Удалить таймер после завершения обработки
  }, 100)
}
```

#### Оптимизация с помощью подкомпонентов

Один из методов оптимизации — разделить проект на независимый компонент, в данном случае добавив компонент «Задача»:
``` HTML
<div on:click="process">
  <p>{{имя }}</p>
  <p>{{ прогресс }}%</p>
</div>
```
Сценарий JavaScript компонента Task может обрабатывать собственные операции Process():
``` js
экспортировать по умолчанию {
  данные: {
    name: null, //Имя задачи должно быть передано из внешнего слоя
    Прогресс: 0
  },
  // Каждый объект компонента Task будет обрабатывать свою собственную операцию процесса,
  // И через это получить доступ к своим собственным реактивным свойствам.
  процесс() {
    это.прогресс = 0
    let timer = setInterval(() => {
      это.прогресс += 10
      если (this.progress >= 100)
        ClearInterval (таймер)
    }, 100)
  }
}
```

По сравнению с предыдущим методом, новое решение можно использовать сразу после [Введение компонента Task](/framework/comment/README.md#Введение компонента):
``` HTML
<task for="задача в задачах" :name="task.name" />
```
Код JavaScript родительского компонента также может быть проще:
``` js
экспортировать по умолчанию {
  данные: {
    задачи: []
  },
  onInit() {
    для (пусть я = 0; я < 10; ++i)
      this.tasks.push({ name: `Task #${i + 1}` })
  }
}
```
Это имеет следующие изменения по сравнению с прямым обновлением списка:
— Вставленный элемент массива не имеет атрибута «прогресс», поскольку его необходимо обработать только в подкомпоненте «Задача»;
- Метод `process()` удален и перенесен в компонент `Task`;
— Нет необходимости использовать переменную индекса `idx` для различения разных элементов.

Этот метод может реализовать тот же интерфейс списка задач, за исключением того, что обработка «прогресса» переносится в подкомпонент «Задача», что позволяет избежать обновления массива задач при изменении хода выполнения. Использование этого метода может оптимизировать проблему обновления внутреннего интерфейса элементов списка и снизить сложность кода.
