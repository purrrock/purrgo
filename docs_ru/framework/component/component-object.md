
# 组件对象

位于 UX 文件内的 `<script>` 标签定义并导出了一个组件对象。一个典型的组件对象定义如下：
``` js
export default {
  data: {
    text: "Hello world"
  },
  onInit() {
    console.log("component onInit()")
  },
  clicked(event) {
    console.log(`clicked: ${event}`)
  }
}
```
组件框架允许开发者为组件对象填写一些属性来实现功能，本文档将介绍这些属性。

## 响应式编程

**响应式编程**是一种用于动态更新界面和数据状态的编程范式。通过**响应式属性**，开发者可以自动追踪数据的变化并更新界面，无需手动触发和管理这些更新。这使得数据与界面始终保持同步，实现简洁高效的 UI 编程体验。

### 响应式属性

组件对象的 [`data` 属性](#data-属性)和 [`computed` 属性](#computed-属性)对象中定义的属性都是组件的**响应式属性**，也称为 view-model 属性：
- **`data` 属性**：直接反映组件的状态。例如，温度值、显示文本或按钮状态等都可以定义在 `data` 中。当这些属性值发生变化时，框架会自动同步到视图中。
- **`computed` 属性**：用于定义基于 `data` 或其他 `computed` 属性计算得到的派生属性。计算属性会自动随依赖数据的变化而更新，使得复杂的逻辑表达更直观、简洁。

总而言之，当组件的响应式属性值发生变化时，依赖这些属性的内容会自动更新并进行渲染，从而保证显示的内容与数据保持一致。

### 自动数据绑定

**自动数据绑定**是响应式编程的核心概念，它使得数据的变化能够直接反映到界面上，而无需开发者手动处理。

由于每个响应式属性与界面的相关部分是自动绑定的，当属性值发生变化时，界面会自动更新，无需调用特定元素的属性更新函数。

Например, определите реактивное свойство с именем counter:
``` js
экспортировать по умолчанию {
  data: { // Определить свойство реагирования счетчика в объекте данных
    счетчик: 0 // начальное значение 0
  }
}
```

Всякий раз, когда значение счетчика изменяется, интерфейс, ссылающийся на это свойство, будет автоматически обновляться. Следующий код [шаблона] демонстрирует этот механизм:
``` HTML
<p on:click="counter += 1">
  счетчик: {{ счетчик }}
</p>
```
В этом примере показано, как нажатие на тег `<p>` приводит к тому, что `counter` отображает счетчик, значение которого увеличивается на 1. Вы можете нажать на онлайн-демонстрацию ниже, чтобы проверить ее:

`{{ counter }}` в теге `<p>` является шаблоном [выражение интерполяции] (template.md#interpolation Expression), и его зависимость от `counter` автоматически привязывается. Видно, что благодаря автоматической привязке данных исключается ручная операция обновления **данных**-**интерфейса** в традиционной разработке графического интерфейса, что делает логику интерфейса более краткой и понятной.

## атрибут `data`

Атрибут data используется для объявления атрибутов реактивных данных компонента. Свойство является объектом, например:
``` js
экспортировать по умолчанию {
  данные: {
    текст: «Привет, мир»
  }
}
```
Чтобы значение атрибута data можно было сериализовать с помощью JSON.stringify(), для точности должны быть выполнены следующие условия:
- Значения простых типов: `число`, `строка`, `логическое`, `нуль` или `неопределенное`
- В объектах и массивах с рекурсивной структурой значение самого глубокого элемента должно принадлежать одному из указанных выше.

Это означает, что свойства объектов данных в исходном коде не могут иметь функции или другие специальные типы значений. Сюда также входят такие объекты, как «Дата».

::: Примечание
Объекты data не поддерживают типы данных, не совместимые с JSON, такие как объекты Date, Proxy и т. д. Это известное ограничение. Если вам нужно использовать эти типы данных, вы можете определить их как [настраиваемые атрибуты](#custom Attributes), в противном случае это приведет к непредсказуемому поведению.
:::

Все свойства data — это свойства модели представления компонента, поэтому данные можно использовать для реактивного программирования. Использование this.prop в объекте компонента позволяет напрямую получить доступ к свойствам объекта data. Итак, в следующем объекте компонента
``` js
экспортировать по умолчанию {
  данные: {
    onInit: правда
  },
  onInit() {}
}
```
Код `this.onInit` будет обращаться к свойству `onInit` в объекте `data` вместо функции жизненного цикла `onInit`.

::: совет
Для оптимизации производительности в объекте data определяются только данные, используемые для рендеринга пользовательского интерфейса и управления состоянием. Для данных, не требующих оперативности, вы можете определить их как [пользовательские атрибуты](#custom Attributes). Например: идентификатор таймера (возвращаемое значение `setTimeout()`), дескриптор [аудиоплеера](/api/system-media.md#createaudioplayer), объект подключения WebSocket и т. д. Такие объекты обычно не нужны в качестве реактивных свойств и не будут работать должным образом.
:::

## `вычисляемый` атрибут

Свойство `computed` объекта компонента объявляет вычисляемые свойства компонента. По сравнению с реактивными свойствами в data, вычисляемые свойства могут реализовывать свойства, требующие некоторых вычислений для получения результата. Например
``` HTML
<текст> перевернутое сообщение: {{reverseMessage }}
```

``` js
экспортировать по умолчанию {
  данные: {
    сообщение: «здравствуйте»
  },
  вычислено: {
    ReverseMessage() { // Это метод получения вычисленного свойства ReverseMessage.
      верните this.message.split('').reverse().join('')
    }
  }
}
```
Здесь объявляется вычисляемое свойство ReversedMessage, которое реализует функцию получения для получения значения свойства. Непосредственно используйте `this.reversedMessage` (`this.` можно опустить в шаблоне), чтобы получить значение вычисляемого свойства.

Вычисляемые свойства также являются свойствами модели представления компонентов. Значение вычисляемого свойства кэшируется, поэтому значение вычисляемого свойства не пересчитывается несколько раз. С другой стороны, вычисляемые свойства автоматически обновляются при изменении свойств модели представления, от которых они зависят. В этом примере значение вычисляемого свойства вычисляется на основе свойства message, поэтому при изменении свойства message значение свойства reversedMessage автоматически обновляется.

### Метод установки вычисляемых свойств

Вычисляемые свойства по умолчанию имеют только методы получения, но вы также можете предоставить методы установки для вычисляемых свойств:
``` js
экспортировать по умолчанию {
  данные: {
    сообщение: «здравствуйте»
  },
  вычислено: {
    перевернутое сообщение: {
      get() { // Это метод получения вычисляемого свойства ReverseMessage.
        верните this.message.split('').reverse().join('')
      },
      набор (значение) {
        this.message = value.split('').reverse().join('')
      }
    }
  }
}
```
В настоящее время значение вычисляемого свойства reversedMessage больше не является функцией, а объектом, который имеет два метода: метод получения `get` и метод установки `set`. Аргументом метода set является новое значение, которому необходимо установить вычисляемое свойство.

## атрибут `watch`

Метод объекта watch используется для отслеживания изменений свойств модели представления, например:
``` js
экспортировать по умолчанию {
  данные: {
    значение: 0
  },
  смотреть: {
    значение (newValue, oldValue) {
      console.log(`изменение значения: ${oldValue} -> ${newValue}`)
    }
  }
}
```
Метод объекта `watch` будет прослушивать изменения в свойстве модели представления с тем же именем, поэтому `watch.value()` прослушивает изменения в свойстве `value`. Изменения вычисляемых свойств также можно отслеживать с помощью функции «наблюдение».

## Пользовательские свойства

Пользователи также могут определять собственные свойства в объектах компонентов, которых нет в модели представления (т. е. нет в объектах данных или вычисляемых объектах) и, следовательно, они не являются реактивными. Разработчики могут определять методы как настраиваемые атрибуты, а также использовать настраиваемые атрибуты для хранения некоторых данных, не требующих оперативности. Например:
``` HTML
<p on:click="onClick()">{{ text }}</p>
```

``` js
экспортировать по умолчанию {
  данные: {
    text: "какой-то текст"
  },
  // Пользовательские свойства не находятся в данных или вычисляемом объекте, а определяются непосредственно в объекте компонента
  timer: null, //Дескриптор таймера хранения, не нужно определять заранее, это свойство будет автоматически создано, когда this.timer будет присвоено значение
  onInit() {
    // Новое свойство, присвоенное этому свойству, является пользовательским свойством
    this.timer = setInterval(() => this.text += "?", 1000)
  },
  onDestroy() {
    очиститьИнтервал (этот.таймер)
  },
  onClick() {
    this.text += "." // Манипулирование свойствами модели представления в пользовательских методах
  }
}
```

Свойство text в этом примере является адаптивным, а свойство timer — неадаптивным. Атрибут `timer` используется для хранения дескриптора таймера. Это значение не имеет ничего общего с представлением интерфейса, поэтому его не нужно использовать в качестве атрибута модели представления. Учитывая стандартизацию кода, пользовательские свойства также могут быть определены заранее в объекте компонента:
``` js
экспортировать по умолчанию {
  данные: {
    text: "какой-то текст"
  },
  timer: null, // Пользовательские свойства — это прямые свойства объекта компонента
  // ...
}
```
Как показано в примере, пользовательские свойства можно определить непосредственно в объекте компонента. Пользовательские свойства для каждого компонента являются отдельными экземплярами и не являются общими.

::: предупреждение
Такие свойства, как пользовательские свойства, объекты данных, вычисляемые объекты, функции жизненного цикла и т. д., не могут иметь одинаковые имена, иначе некоторые свойства будут перезаписаны и недоступны.
:::

### Метод

Пользовательские свойства и методы являются прямыми свойствами объекта компонента и по существу эквивалентны. Когда вы назначаете функцию свойству объекта-компонента, свойство становится методом. В этом разделе эта эквивалентность демонстрируется на двух примерах.

Метод 1: Непосредственно определить метод. Это наиболее распространенный и рекомендуемый способ написания.
``` js
экспортировать по умолчанию {
  данные: {
    количество: 0
  },
  приращение() {
    это.count++
  }
}
```

Способ 2. Определите атрибуты и присвойте значения функциям.
``` js
экспортировать по умолчанию {
  данные: {
    количество: 0
  },
  приращение: функция() {
    это.count++
  }
}
```
Оба метода записи полностью идентичны по функциям и могут вызываться через this.increment(). То же самое при использовании в шаблоне:
``` HTML
<button on:click="increment()">Количество: {{ count }}</button>
```

::: совет
Рекомендуется использовать метод 1, который представляет собой синтаксис объектного метода, поддерживаемый стандартом ES6+, и является более кратким и понятным.
:::

### Метод динамического назначения

Помимо определения методов непосредственно в объекте компонента, вы также можете динамически назначать методы после создания экземпляра компонента (например, в жизненном цикле onInit). Ключевой особенностью этого подхода является то, что динамические методы каждого экземпляра компонента независимы и могут захватывать и поддерживать различные состояния посредством замыканий.

Рассмотрим компонент таймера, где каждый экземпляр имеет свой счетчик и может быть остановлен независимо. Это типичный сценарий применения метода динамического назначения:
``` HTML
<дел>
  <text>тайм-аут: {{ counter }}</text>
  <button on:click="stopTimer">Стоп</button>
</div>
```

``` js
экспортировать по умолчанию {
  данные: {
    счетчик: 0,
  },
  stopTimer: null, // Необязательно: предопределенный метод stopTimer
  onInit() {
    константный таймер = setInterval(() => {
      это.counter++
    }, 1000)
    //Динамически создаем метод stopTimer и захватываем переменную таймера посредством замыкания
    this.stopTimer = () => {
      ClearInterval (таймер)
      this.stopTimer = null // Оставляем метод пустым после остановки
    }
  },
}
```

В следующем примере одновременно создаются экземпляры 4 компонентов таймера. Вы можете попытаться остановить любой из них самостоятельно:

<glyphix id="comComponent-object-dynamic-method" height="200" width="300" inline>
</глификс>

Реализация этого метода динамического назначения опирается на следующие ключевые моменты:
- **Захват замыкания**: константа `timer`, созданная в `onInit`, является локальной переменной, а метод `stopTimer` захватывает эту переменную посредством замыкания.
- **Независимость экземпляра**: каждый экземпляр компонента создаст свои собственные `timer` и `stopTimer` при вызове `onInit`, и они не будут мешать друг другу.
- **Изоляция состояния**: нажатие кнопки «Стоп» экземпляра останавливает таймер только этого экземпляра и не влияет на другие экземпляры.

Конечно, в этом примере чаще всего метод stopTimer определяется непосредственно в объекте компонента:
``` js
экспортировать по умолчанию {
  данные: {
    счетчик: 0,
  },
  таймер: ноль,
  onInit() {
    // В этом случае таймер необходимо сохранить как пользовательский атрибут
    this.timer = setInterval(() => {
      это.counter++
    }, 1000)
  },
  стопТаймер() {
    // Метод stopTimer обращается к this.timer, чтобы остановить таймер
    очиститьИнтервал (этот.таймер)
    this.timer = null // Очистить ссылку на таймер
  }
}
```
Обычно это более интуитивно понятно для таймеров, но если некоторые из них имеют сложный контекст и требуют стратегий динамического распределения, для реализации более гибкой логики можно использовать методы динамического назначения. В следующей таблице показана разница между динамическими методами и напрямую определенными методами:

| Особенности | Метод прямого определения | Метод динамического назначения |
|------|------------|------------|
| Возможность совместного использования | Все экземпляры используют один и тот же объект функции | Каждый экземпляр имеет независимую копию функции |
| Закрытие захвата | Не захватывает локальные переменные в области | Может захватывать локальные переменные в области |
| Использование памяти | Меньше (совместно) | Чуть больше (одна копия на экземпляр) |
| Применимые сценарии | Общие операции без гражданства | Операции по захвату местных государств |
