
#медиазапрос

Медиа-запросы позволяют разработчикам использовать разные стили в зависимости от типов устройств. В настоящее время медиа-запросы поддерживают правило CSS `@media`, но атрибут компонентов `media` пока не поддерживается.

## Правила CSS `@media`

Синтаксис правила `@media`:
``` CSS
@media <условие запроса> {
  <css-правила>
}
```
[`<условие запроса>`](#query условие) используется для запроса типов и характеристик мультимедиа и может комбинироваться с помощью различных логических операторов. Правила CSS в `<css-rules>` вступят в силу при выполнении условий медиа-запроса. Например
``` CSS
@media screen и (форма: круг) {
  @import "circle.css";
}
```
Используйте правило `@import "circle.css"` только на устройствах с круглыми экранами. `<css-rules>` может быть любым правилом CSS, включая любое количество правил `@import`, `@font-face`, селекторов, `@media` и т. д.

## Атрибут `media-query` компонента

Вы можете использовать атрибут `media-query` для любого компонента, чтобы использовать медиа [условия запроса] (#queryconditions), чтобы определить, отображается ли компонент. Например
``` HTML
<div media-query="(форма: круг)">
  ...
</div>
```
`<div>` — это компонент, который будет отображаться только на устройствах с круглыми экранами.

Атрибут media-query будет обрабатываться только на этапе упаковки, а компоненты, не соответствующие условиям медиа-запроса, будут удалены напрямую. Если элементы, которые необходимо выбрать с помощью атрибута `media-query`, более сложны, вы можете рассмотреть возможность использования [макроса шаблона](../компонент/template-macro.md).

## Условия запроса

Условие запроса представляет собой выражение следующей структуры:
``` ебнф
(*выражение медиа-запроса *)
<запрос> := <запрос> и | или | , <query> (* Вы можете использовать и или , чтобы объединить логику *)
         | (не <запрос>) (* не выражение *)
         | <тип-медиа> (*тип носителя *)
         | (<функция>: <значение>)
         | (<объект> <relop> <значение>)
         | (<значение> <relop> <функция> <relop> <значение>)
(* оператор отношения *)
<релоп> := < | <= | > | >=
```
Среди них `<media-type>` — это [тип мультимедиа] (#media type), `<feature>` — это любая [медиа-функция] (#media Feature), а `<value>` — это значение, поддерживаемое медиа-функцией. Ниже приведены допустимые выражения условий запроса:
``` CSS
@media экран { ... }
@media screen and (форма: прямоугольник) и (ширина <500 пикселей) { ... }
@media not (shape: rect) { ... } /* Это эквивалентно выбору круглого экрана */
```

### Логические операторы

Используйте `and`, `or` и `,` для объединения нескольких выражений условий запроса и используйте оператор `not` для отрицания условия запроса. Вы также можете использовать круглые скобки для повышения приоритета операторов:
``` CSS
@media (не (ширина < 500 пикселей)) или (ориентация: книжная) { ... }
```
Значения различных операторов следующие:
- Удовлетворяет «А» и «В», когда удовлетворены оба «А» и «В»;
- `A и B` и `A, B` удовлетворяются, когда удовлетворяется одно из `A` или `B`;
- «не А» не удовлетворено, когда удовлетворено «А», и наоборот.

### Операторы отношения

Некоторые свойства мультимедиа поддерживают операторы отношения, такие как ширина:
``` CSS
@media (ширина > 500 пикселей) { ... } /* Выбор устройств с шириной более 500 пикселей */
@media (400px < ширина <= 600px) { ... } /* Поддержка сравнения диапазонов */
```
Существует 4 типа операторов отношения: `<`, `<=`, `>`, `>=`.

## Атрибуты запроса

### Тип носителя

Тип носителя — это имя. В настоящее время поддерживается только тип носителя «экран». `screen` также является типом носителя по умолчанию, поэтому его не нужно писать.

### Свойства мультимедиа

#### `ширина`

Запрос ширины экрана устройства с поддержкой операторов отношений. Значение должно быть в пикселях, например 500px.

#### `максимальная ширина`

Определяет максимальную ширину экрана. Единицей значения должно быть «px». `(max-width: 500px)` эквивалентно `(width <= 500px)`.

#### `минимальная ширина`

Определяет минимальную ширину экрана. Единицей значения должно быть «px». `(min-width: 500px)` эквивалентно `(width >= 500px)`.

#### `высота`

Запрос высоты экрана устройства с поддержкой операторов отношений. Значение должно быть в пикселях, например 500px.

#### `максимальная высота`

Определяет максимальную высоту экрана. Единицей значения должно быть «px». `(max-height: 500px)` эквивалентно `(height <= 500px)`.

#### `минимальная высота`

Определяет минимальную высоту экрана. Единицей значения должно быть «px». `(min-height: 500px)` эквивалентно `(height >= 500px)`.

#### `форма`

Определяет форму экрана. Поддерживаемые значения:
- `rect`: представляет собой прямоугольный экран;
- «круг»: обозначает круглый экран;

#### `соотношение сторон`

Запрос соотношения сторон экрана с поддержкой операторов отношений. Значение может быть числом или дробью, например, «1,5» и «3/2» обозначают соотношение сторон $3/2$.

#### `максимальное соотношение сторон`

Указывает максимальное соотношение сторон экрана устройства.

#### `минимальное соотношение сторон`

Указывает минимальное соотношение сторон экрана устройства.

#### `ориентация`

Определяет форму экрана. Поддерживаемые значения:
- «портрет»: указывает на устройство с вертикальным экраном;
- «Пейзаж»: указывает на горизонтальное устройство экрана.

#### `профиль-памяти`

Атрибут профиля памяти — это справочное значение, которое помогает разработчикам сократить функциональность при различных бюджетах памяти. Он устанавливается на основе таких параметров, как реальный объем памяти устройства и разрешение экрана. Профили памяти могут помочь разработчикам оптимизировать и настроить функции в соответствии с установленным бюджетом памяти, чтобы обеспечить бесперебойную работу приложений на устройствах начального уровня.

Атрибут `memory-profile` поддерживает следующий синтаксис:
``` ебнф
 Memory-profile := <число> (* размер конфигурации памяти, единица измерения по умолчанию — КиБ *)
                 | <число> K (* Размер конфигурации памяти в КиБ *)
                 | <число> M (* размер конфигурации памяти, единица измерения — МиБ, может быть десятичной *)
```

Обратите внимание, что «профиль памяти» не является фактической емкостью памяти устройства. Вообще говоря, значения этого атрибута распределяются следующим образом:
- $2048$ ($2\rm M$): устройства менее $2\rm MiB$ относятся к устройствам начального уровня. Приложениям следует отсекать списки типа «рыбий глаз», длинные списки с большим количеством изображений и т. д. Некоторые сложные страницы, возможно, также придется упростить или исключить.
- $4096$ ($4\rm M$): устройства стоимостью менее $4\rm MiB$ относятся к устройствам среднего и низкого уровня. Небольшое количество списков типа «рыбий глаз» можно использовать в приложениях, однако не рекомендуется использовать слишком длинные списки с картинками.
- $8192$ ($8\rm M$): устройства стоимостью менее $8\rm MiB$ представляют собой устройства среднего и высокого класса, которые в основном могут использовать все функции, но производительность можно улучшить за счет большей емкости.

Например, следующий запрос лиганда сопоставляет устройства с профилями памяти между $2{\rm MiB}\sim 4{\rm MiB}$:

``` CSS
@media (2M <профиль памяти <= 4M) {
  /* Специальный набор правил CSS */
}
```

Если вам нужно получить профиль памяти устройства в JavaScript, используйте атрибут [`memoryProfile`](/api/system-device.md#memoryprofile) модуля `@system.device`.
