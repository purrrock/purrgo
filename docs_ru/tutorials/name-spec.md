#Соглашение об именовании компонентов

В этом документе описаны обязательные соглашения об именах и рекомендуемые стили именования для компонентных инфраструктур. Среди них обязательное соглашение об именах имеет обязательные требования. Если не следовать, эффект может не оправдать ожиданий. Использование рекомендуемого соглашения об именах обеспечивает максимальную совместимость.

## Соглашение об именовании шаблонов

Имена тегов в шаблонах должны быть указаны в регистре kebab или PascalCase:
``` HTML
<Кнопка></Кнопка>
<кнопка></кнопка>
<область прокрутки></область прокрутки>
<ScrollArea></ScrollArea>
```

Имена атрибутов должны быть тире или в номенклатуре CamelCase:
``` HTML
<comComponent prop-name="expr"></comComponent>
<comComponent propName="expr"></comComponent>
```

Рекомендуется использовать номенклатуру тире, соответствующую веб-стандартам.

## Соглашение об именовании кода JavaScript


Имена компонентов в коде JavaScript должны быть в формате Pascal, а в шаблонах используются соответствующие дефисы.

Имена свойств компонентов в коде JavaScript должны быть в верблюжьем регистре:
``` js
экспортировать по умолчанию {
  данные: {
    propName: 0 //Имя атрибута в шаблоне — prop-name
  }
}
```
Эти имена атрибутов будут автоматически преобразованы в соответствующие имена тире в коде шаблона.

## Соглашение об именах файлов

Файл UX должен использовать то же имя, что и компонент, то есть именование в Паскале. В теге `<import>` атрибут `src` должен быть URL-адресом файла с учетом регистра, а атрибут `name` должен быть назван с использованием именования Pascal или тире:
``` HTML
<import src="path/to/UxFile" name="UxFile"/>
<import src="path/to/UxFile" name="ux-file"/>
```
Фактически требования к именованию атрибута name соответствуют именам тегов в шаблоне.
