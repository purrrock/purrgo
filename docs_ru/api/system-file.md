
# Операции с файловой системой

Этот модуль предоставляет API для работы с файловой системой в стиле Promise. обратного вызова, стиль Promise Позволяет избежать ада обратных вызовов и снизить сложность кода.

::: предупреждение
поскольку API файла обратного вызова ошибок при синхронизации, парализме и обработке ошибок, настоятельно рекомендуется использовать [Promise/`await` API](./README.md#Quick Application Asynchronous Interface); Подробные рекомендации можно найти в разделе ловушки и предложения).

Все API в операции `@system.file`), которые имеют отношение к синхронному доступу к вводу-выводу. Обещание и асинхронность/ожидание.
:::

## Распространенные ошибки и предложения

Все последующие причины основаны на типичных проблемах, записанных в стиле обратного вызова, почему его легко недействительно или трудно поддерживать в файле IO, и эквивалентном переписывании Promise/`await`.

### Асинхронные файловые операции

Все API в модуле @system.file являются **асинхронными операциями**. Функция файловой операции, функция возвращается немедленно, не ожидая подтверждения фактической операции ввода-вывода. Обещать.

:::опасность Обязательно прочтите новичкам
Если вы новичок в асинхронном программировании, обязательно внимательно прочитайте этот раздел. **Игнорирование возвращаемых значений асинхронной операции** или **Не ожидайте выполнения обещания** может привести к серьезным ошибкам программы, которые могут не произойти в симуляторе, но могут привести к потере данных или ошибкам программы на мобильном устройстве.
:::

#### Что такое асинхронная операция?

синхронное программирование кодирования выполняется последовательно, а запись строки кода выполняется до выполнения следующей строки:```js
// Пример синхронного кода (псевдокод, файловый API не предоставляет синхронную версию): блокировка ожидания чтения файла
const text = file.readTextSync({uri: 'internal://files/data.txt' });
console.log(текст); // Содержимое файла обязательно будет выведено
console.log('Чтение завершено');
```Но в асинхронном программировании операции ввода-вывода не блокируют выполнение кода. вызывает асинхронную функцию, она немедленно возвращает объект Promise, фактические операции с файлами постоянно в фоновом режиме:```js
// Ошибка: игнорировать обещание, не ждать завершения операции (вызов немедленно возвращается)
file.readText({uri: 'internal://files/data.txt' });
console.log('Эта строка кода будет выполнена немедленно, и чтение файла может быть еще не завершено!');

// Правильно: используйте await, чтобы дождаться завершения операции
const text = await file.readText({uri: 'internal://files/data.txt' });
console.log(текст); // На этом этапе файл прочитан и его можно безопасно использовать
console.log('Чтение завершено');
```#### Почему мы должны использовать ожидание?

Неиспользование ожидания завершения асинхронной операции может привести к возникновению следующей проблемы.

Данные использовались до того, как они будут готовы:```js

::: предупреждение.
В симуляторе разработки файлов операции выполняются практически мгновенно благодаря чрезвычайно высокой скорости ввода-вывода компьютера. Код в симуляторе «просто работает», даже если он неправильно использует `await`.
:::

Ввод-вывод файловой системы на собственных встроенных устройствах имеет следующие ограничения:
- Скорость чтения и записи флэш-памяти необходимы;
- Возможности кэширования файлов слабой системы, чтение и запись файлов обычно осуществляются непосредственно на носителе данных;
- Системные ресурсы ограничены, операция ввода-вывода будет поставлена ​​в свою очередь и задержана.

Код, не использующий `await`, почти наверняка сломается на случайном устройстве! Не нарушайте соглашение асинхронного программирования только потому, что тесты симулятора пройдены.

   const content = await file.readText({uri: 'internal://files/data.txt' });

- Все API `@system.file` являются асинхронными и должны использовать `await` для ожидания.
- Неиспользование ожидания может привести к таким серьезным проблемам, как неподготовленные данные, неупорядоченные операции, потерянные ошибки и повреждение данных.
— Прохождение испытания симулятора не означает, что код правильный. Ввод-вывод на мгновенном устройстве происходит медленнее, и выявляются проблемы.
— Использование `async/await` + `try/catch` — правильный и наиболее краткий способ написания.
- Никогда не игнорируйте возвращаемое значение обещания.

### Ловушка обратного вызова

#### Иллюзия заказа обратного вызова и освещения гонок

Этот тип протокола включает в себя последовательность операций, в ходе которых набор файлов читается, изменяется и записывается. обратный вызов для вызова стиль обратного вызова:```js
// Ожидаем +1 для подсчета файла, но два одновременных вызова могут перезаписать друг друга
функция приращения (uri, сделано) {
  файл.readText({
    ури,
    успех (текст) {
      const n = Число(текст || '0') + 1;
      console.log(`прочитайте ${text}, напишите ${n}`);
      // Вложенная операция записи файла в обратном вызове успеха readText()
      file.writeText({
        ури,
        текст: Строка(n),
        успех () {готово && сделано (); },
        error(msg, code) { Done && Done(new Error(`${msg}:${code}`)); }
      });
    },
    error(msg, code) { Done && Done(new Error(`${msg}:${code}`)); }
  });
}

//Сначала создаем файл счетчика, а затем запускаем его дважды одновременно +1
file.writeText({
  URI: 'внутренний://файлы/счетчик',
  текст: '0',
  успех () {
    //Приращение триггера дважды одновременно, но без синхронизации
    приращение('внутренний://файлы/счетчик');
    приращение('внутренний://файлы/счетчик');
  }
})
```После запуска сценария вы можете увидеть только два журнала «чтение 0, запись 1», а итоговое правило файла «счетчик» будет «1» вместо ожидаемого «2». запись перезаписывает первую запись, в результате чего получается только +1.

::: Примечание
