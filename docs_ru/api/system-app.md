### `terminate` <decl type="(): void" метод version="0.8"/>

Завершить текущее приложение. пользователю потребуется перезапустить приложение, чтобы продолжить его использование.

::: обратите внимание на совместимость рисков
Эти API доступны не на всех платформах, в качестве альтернативы можно использовать метод [`launch.exit()`](./system-launch.md#exit).
:::

### `loadLibrary` <decl type="(имя: строка): объект | неопределенный" метод/>

Загружает загрузчик библиотеки, зарегистрированную собственную реализацию по имени, и вызывает соответствующую библиотеку объекта. зарегистрирована, возвращается `undefined`.

ПРИЛОЖЕНИЕ:```js
// приложение.js
импортировать приложение из @system.app

экспортировать по умолчанию {
  customLib: app.loadLibrary('custom-library'),
  onCreate() {
    если (!this.customLib) {
      // Обработка сбоя загрузки библиотеки, например, возврат к реализации сценария
      this.customLib = someStubImplementation();
    } еще {
      //Используем библиотечные объекты как обычно
      this.customLib.someFunction()
    }
  }
}
```Таким образом, компонент может напрямую использовать this.$app.customLib для доступа к библиотеке объекта.

`loadLibrary()` определяет, является ли возвращаемым значением «неопределенным», чтобы определить, поддерживает ли текущая платформа платформы, тем самым переходя к реализации сценария в среде среды симулятора, не полагаясь на обработку симулятора другими способами к модулям.

Если вашему приложению необходимо поддерживать стандартные API-интерфейсы быстрого приложения, а также функции настройки системы, вы можете решить, следует ли выполнить откат, на основе результата, возвращаемого `loadLibrary()`.

### `keepForeground` <decl type="(options: { Enable: boolean }): void" метод/>

Устанавливает, остается ли приложение на переднем плане. Значение правда, приложение пытается оставаться на переднем плане.

Для использования этого метода необходимо объявить разрешение приложения для `watch.permission.FOREGROUND_SERVICE` в файле [`manifest.json`](/framework/application/manifest.md#permissions).

Этот метод является лишь лишь упоминанием о системах управления и не является обязательным. Применение может быть переведено в фоновый режим из-за действий пользователя или другого политика с соблюдением высокого приоритета. Переднем плане устройство все равно может перейти в режим пониженного энергопотребления:

- Пользовательского интерфейса будет уменьшено.
- В противном случае экран через некоторое время выключается, но приложение продолжает работать на переднем плане.

Когда устройство переходит в режим пониженного энергопотребления (включая выключение экрана), приложение переднего плана по-прежнему будет планироваться и выполняться с более низким энергопотреблением, а не полностью перейти в спический режим. навигации или фитнес-приложений.
