### `принести`
<метод объявления><pre>
(варианты: {
  URL: строка,

  заголовок?: {[ключ: строка]: строка},
  параметры?: {[ключ: строка]: строка | номер},
  данные?: строка | МассивБуфер | {[ключ: строка]: любой},
  тип ответа?: 'текст' | 'json' | 'массивбуфер',
  тайм-аут?: число
}): Обещание<{
  код: номер,
  заголовки: {[ключ: строка]: строка},
  данные: строка | МассивБуфер | любой,
}>
</pre></decl>

Инициировать асинхронный запрос сетевых данных.
- `url`: URL-адрес веб-сайта, к которому осуществляется доступ.
- `метод`: поддержки `'GET'`, `'POST'` и `'PUT'`, по умолчанию используется `'GET'`.
- `header`: объект, каскадная информация заголовка HTTP-запроса, ключ и значение являются строками. Типичными полями заголовка HTTP могут быть `Authorization`, `Content-Type` и т. д. д.
- `params`: параметры запроса, которые будут сохранять все свои свойства для URL-части запроса.
- `данные`: часть тела запроса HTTP POST.
- `responseType`: тип данных ответа в HTTP-запросе. следующие значения.
  - `'текст''`: ответ возвращает текстовые данные, то есть атрибутные данные, передаваемые данные имеют тип `строка`.
  - `'json'`: ответ возвращает данные JSON, а возвращаемые атрибутные данные будут анализировать данные JSON в соответствии со значением JavaScript.
  - `arraybuffer`: ответ возвращает двойные данные, то есть возвращаемые данные данных в объекте `ArrayBuffer`.
- `timeout`: тайм-аут ответа на запрос в миллисекундах, значение по умолчанию — $6000\rm ms$.

#### параметр `данные`

`data` — это тело запроса, которое используется только в запросах POST. Обычно он бывает трех типов: строка, объект ArrayBuffer или объект JSON. Когда речь идет о текстовом объекте JSON, оно сериализуется в текстовой форме. (метод параметра):
- Если Content-Type имеет значение application/json, сериализуйте данные параметра объекта в формате JSON в качестве запроса тела;
— В других случаях сериализуйте данные параметра объекта в формате application/x-www-form-urlencoded.

::: предупреждение
Многие HTTP API тело запроса POST в формате JSON. должно быть правильно определено значение application/json.
:::

#### Возвращаемое значение

Возвращаемый объект Promise соблюдается:
- [`code`](#code-response code) — код ответа сервера.
- `header` — заголовок ответа сервера.
- `data` — это возвращаемое значение запроса данных, особый критерий, определяемый параметром `options.responseType`.

В случае сбоя запроса возвращенный объект Promise будет отклонением.

## Инструкция по применению

### `code` ответ на код

Код ответа, возвращаемый сервером, означает:
- `200`: указывает, что запрос успешен;
- `1002`: Ошибка проверки параметра;
- `1005`: входные параметры неполные;
- `5000`: запрос не выполнен, ошибка ответа;
- `5001`: не удалось записать буфер данных;
- `5002`: запрос не выполнен, ошибка ответа;
- Другие: другие коды ответов HTTP/HTTPS, например «404» и т. д. д.

Когда код ответа, возвращаемый [`fetch`](#fetch), равен `200`, это означает, что сетевой запрос успешен, а если это другие значения, это означает, что в запросе есть ошибка.

## Пример

### ПОЛУЧИТЬ запрос

Вот базовый пример запроса GET:``` js
const res = await fetch.fetch({
  URL: 'http://www.rt-thread.com/service/rt-thread.txt',
  метод: 'GET', // Поскольку режим по умолчанию — GET, в настоящее время метод не является обязательным
  Тип ответа: 'текст'
})
console.log(`код состояния ответа: ${res.code}`)
console.log(`данные ответа: ${res.data}`)
```###ПОСТ-запрос``` js
