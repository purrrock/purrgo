
#таймер

Этот модуль обеспечивает функцию таймера для отложенного или периодического выполнения кода.

##Определение интерфейса

### `setTimeout` <decl type="(callback: () => void, period: Number: Number" />

Установите таймер для выполнения функции обратного вызова после отображения времени задержки. Описание параметра:
- `обратный вызов`: функция обратного вызова, которая будет выполнена после достижения времени задержки;
- `duration`: время задержки, единица измерения — миллисекунды.

Возвращает идентификатор таймера, который можно использовать для отключения таймера с помощью метода [`clearTimeout()`](#cleartimeout).

Пример:``` js
//Выполняем функцию обратного вызова через 1 секунду
const timerId = setTimeout(() => {
  console.log('Прошла 1 секунда')
}, 1000)
```### `setInterval` <decl type="(callback: () => void, period: Number: Number" />

Установите таймер для многократного выполнения функции обратного вызова в соответствии с приведенным периодом. Описание параметра:
- `обратный вызов`: каждый раз, когда срабатывает таймер;
- `длительность`: период выполнения, единица измерения — миллисекунды.

Возвращает идентификатор таймера, который можно использовать для отключения таймера с помощью метода [`clearInterval()`](#clearinterval).

Пример:``` js
//Выполнять функцию обратного вызова каждые 500 миллисекунд
const timerId = setInterval(() => {
  console.log('Прошло еще 500 миллисекунд')
}, 500)
```### `clearTimeout` <decl type="(timerId: Number): void" />

Отменяет таймер, установленный метод [`setTimeout()`](#settimeout). Параметр timerId — это идентификатор таймера, который нужно отменить.

::: предупреждение

Используйте установку для идентификатора значения «null» после проверки таймера, чтобы функция ClearTimeout()` могла безопасно принимать недопустимые идентификаторы, такие как `null`, `0` и т. д. д., и эти вызовы не будут иметь переключающих эффектов.
:::

Пример:``` js

## Примечания по разработке

### Повторное использование идентификатора таймера

Существует одно главное отличие между этой реализацией и утверждением веб-стандартов: **Идентификаторы таймеров могут использоваться повторно**.

В веб-браузерах и Node.js каждый вызов setTimeout() или setInterval() возвращает уникальный, монотонно увеличивающийся идентификатор, который не используется повторно. `clearTimeout()` `clearInterval()` будет иметь переключающие эффекты.

Однако в этом таймере активации идентификатора используется ограниченный пул идентификаторов, и когда таймер очищается или завершается, его идентификатор может быть повторно использован повторно созданным таймером. тот же идентификатор (т. е. число, возвращаемое замедление setTimeout() или setInterval()), вы можете случайно остановить работу другого таймера.

`clearTimeout()` и `clearInterval()`, такие как `null`, `0`, `unknown` и т. д. д., и эти вызовы не будут иметь переключающих эффектов.

Поэтому важно следовать за лучшими практиками:
1. Каждый идентификатор таймера очищается только один раз;
2. После очистки установите для идентификатора таймера значение «ноль», «0» или «неопределено», чтобы избежать случайной повторной очистки.

Таймер API **не гарантирует точные временные интервалы**, и фактическое время выполнения может быть получено. Это потому, что:
- Ограничения системного планирования и производительности могут привести к тому, что время включения таймера будет неточным;
- Минимальный зависит от политики низкого энергопотребления.

Поэтому не используйте API-таймер для точного расчета времени. Если вам нужно измерение Дата посещения: февраль 2018 г. получение фактической метки времени.

#### Пример ошибки: использование счетчика-таймера для измерения времени

    }, 1000)
  },
  onDestroy() {
    ClearInterval(this.timerId)
  },
}
```$1000\rm мс$, фактический интервал запуска может составлять $1010\rm мс$ или даже больше. Кумулятивные ошибки приводят ко все более неточному расчету времени. точности или напрямую приостанавливаться.

#### Правильный пример: использование даты объекта для определения времени

Правильный подход — записать начальную метку времени, а затем вычислить разницу с текущим временем при каждом обновлении:``` js

      this.elapsedTime = Date.now() - this.startTime

  },

  },
  onDestroy() {

  },
}
