
# Руководство по глобальной миграции ресурсов

Эта статья предназначена для проектов последующей интеграции Glyphix и помогает вам обновить метод загрузки глобальных ресурсов в исторических проектах до новейшего решения, получить глобальный макет ресурсов, которым легко управлять и редактировать, и больше не полагаться на поддержку упаковки или инструментов преобразования производителя.

Вначале Glyphix использовал двоичный архивный пакет global.pkg для управления глобальными ресурсами (файлами шрифтов, таблицами сопоставления шрифтов и т. д.). Позже он постепенно эволюционировал и стал напрямую использовать неупакованные файлы ресурсов. Наконец, формат файла сопоставления шрифтов также был преобразован из двоичного в стандартный JSON <version-badge с="0.9" />. Если код входа, который вы поддерживаете, по-прежнему использует старый метод записи, вы можете обновить его в соответствии с этой статьей.

::: совет
Использование старой модели сопряжено с такими проблемами, как проблемы с обслуживанием и трудности с управлением и редактированием глобальных ресурсов. Рекомендуется немедленно обновиться.
:::

## Удалить `global.pkg`

### Характеристики старого кода

Если в вашем входном коде присутствует какой-либо из следующих шаблонов, вы используете global.pkg:```cpp
EnvPath::setEntry(EnvPath::GlobalPackage, "/global.pkg");
static String globalUri(const String &path) { return "pkg:///" + path; }
```Эффект этих двух строк заключается в маршрутизации всех запросов ресурсов протокола `pkg:///` в файл `/global.pkg` внутри пакета двоичного архива.

Почему его необходимо удалить:
- Каждый раз, когда вы меняете ресурс, такой как шрифты, вам необходимо перезапустить пакет инструмента, чтобы сгенерировать файл `.pkg`.
- во время отладки `.pkg` во время отладки, а также сложная проверка на соответствие требованиям.
- Процесс производства требует использования специальных инструментов, что увеличивает затраты на связь и обслуживание.

### Операция переноса

**Шаг первый: извлеките ресурсы из файла global.pkg. **

Global.pkg`, Global.pkg`, Global.pkg`, Global.pkg`, Global.pkg` Обычно необходимо решить следующее:```
шрифты/
    NotoSans-Regular.ttf
    NotoSansSC-Regular.ttf

```Поместите извлекаемый каталог в каталог ресурсов вашего проекта, например `/fonts/`.

**Шаг 2. Удалите код, связанный с `global.pkg`. **

1. Удалите таблицу `EnvPath::setEntry(EnvPath::GlobalPackage, "/global.pkg")`
2. Удалите функции-оболочки, такие как `globalUri()`.
3. Замените все ссылки на ресурс `pkg:///xxx` на прямой путь к файлам, то есть `/xxx`.

## Вместо этого воспользуйтесь файлом распределения шрифтов JSON

### Характеристики старого кода```cpp
FontFaceMap &map = App()->fontManager()->faces();
map.readFile("/fonts/font-faces");
````readFile` читает файл пользовательского двойного формата. вручную, его необходимо преобразовать из файла CSS с помощью инструментария package.

### Описание формы JSON

Теперь мы напрямую шрифтов. шрифт-faces.json» шрифт-faces.json:```json
{
  "шрифты": [
    {
      "семейный": "без засечек",
      «вес»: 400,
      «стиль»: «нормальный»,
      "ссылки": [
        "NotoSans-Regular.ttf",
        "NotoSansSC-Regular.ttf",
        "NotoSansJP-Regular.ttf"
      ]
    },
    {
      "семейный": "без засечек",
      «вес»: 700,
      «стиль»: «нормальный»,
      "ссылки": [
        "NotoSans-Bold.ttf"
      ]
    },
    {
      "семья": "засечки",
      «вес»: 400,
      «стиль»: «нормальный»,
      "ссылки": [
        "NotoSerif-Regular.ttf"
      ]
    }
  ]
}
```Описание поля:

| Поле | Тип | Требуется | Значение по умолчанию | Описание |
|------|------|------|--------|------|
| `семья` | Строка | Да | - | Название основных шрифтов, например `sans-serif`, `serif` |
| `вес` | Целое число | Нет | 400 | Значение толщины шрифта CSS (100–900), 400 — обычный, 700 — жирный |
| `стиль` | строка | нет | нормальный |
| `URL-адреса` | строковый массив | да | - | путь к файлу шрифта относительно каталога, в котором находится файл JSON |

Ключевые поля подробно описаны ниже.

**вес полюса**

Вес напрямую заполняет значение веса шрифта CSS, которое будет округлено до ближайшего стандартного значения:

- `100` Тонкий
- 400` Regular (значение по умолчанию, просто оставьте поле пустым)
- `700` Жирный
- `900` Черный

**разрешение пути URL**

JSON. JSON. находится в `/fonts/font-faces.json`, тогда запись `"fonts/NotoSans-Regular.ttf"` в `urls` в конечном итоге будет проанализирована как `/fonts/fonts/NotoSans-Regular.ttf`.

Поэтому рекомендуется размещать файл JSON непосредственно в том же каталоге, что и шрифт файла, чтобы URL-адрес мог напрямую записать имя файла.```
/шрифты/
    шрифт-faces.json
    NotoSans-Regular.ttf
    NotoSansSC-Regular.ttf
    NotoSans-Bold.ttf
```На данный момент требования JSON выглядят так, как показано в приведенном выше коде.

### Модификация кода

Замените `readFile` в коде реализации на `readJSON`:```cpp
#include "gx_fontmanager.h"

статическая пустота setupFont() {
    auto &map = App()->fontManager()->faces();
    if (!map.readJSON("/fonts/font-faces.json"))
        LogError() << "Не удалось загрузить font-faces.json";
    App()->setFont(Font("sans-serif", 24));
}

интервал основной() {
    Приложение-приложение;
    настройкаШрифт();
    // ...
}
```Для этого изменения вызова API остальную часть кода изменять не нужно. напрямую изменить `font-faces.json`, чтобы добавить или удалить шрифты или настройки отношений обсуждения без каких-либо инструментов преобразования.

## Часто задаваемые вопросы

**Как быть с темой, что одно и то же семейство имеет несколько вариантов, таких как обычный, жирный, курсивный и т.д.? **

Добавьте отдельную запись для каждого выражения в массив «font-faces», отличающиеся по «весу» и «стилю»:```json
{
  "шрифты": [
    {
      "семейный": "без засечек",
      «вес»: 400,
      «стиль»: «нормальный»,
      "urls": ["NotoSans-Regular.ttf"]
    },
    {
      "семейный": "без засечек",
      «вес»: 700,
      «стиль»: «нормальный»,
      "urls": ["NotoSans-Bold.ttf"]
    },
    {
      "семейный": "без засечек",
      «вес»: 400,
      "стиль": "курсив",
      "urls": ["NotoSans-Italic.ttf"]
    }
  ]
}
```В проектах MCU обычно используются только обычные шрифты без засечек с «нормальным» весом, и система автоматически откатывается назад.

**Можно ли поместить несколько файлов в URL-адреса массива? Когда это необходимо? **

Может. шрифты файлов в одном массиве URL. буквы, китайские, японские и корейские символы, а также арабский язык:```json
{
  "семейный": "без засечек",
  «вес»: 400,
  «стиль»: «нормальный»,
  "ссылки": [
    "NotoSans-Regular.ttf",
    "NotoSansSC-Regular.ttf",
    "NotoSansJP-Regular.ttf",
    "NotoSansArabic.ttf"
  ]
}
```Когда механизм отображает текст, он ищет символы-глифы в этих файлах по порядку и использует первый соответствующий глиф.

**JSON? **

JSON. JSON. Путь для размещения шрифтов в подкаталогах. Вы также можете указать путь, который не влияет на каталог JSON.

**Могу ли я передать текст JSON непосредственно в коде? **

Может.```cpp
map.readJSON("/fonts/", R"({
  "шрифты": [
    {"family": "sans-serif", "urls": ["NotoSans-Regular.ttf"]}
  ]
})");
```Первый параметр — baseUri, который используется для разрешения относительных путей в URL-адресах.
