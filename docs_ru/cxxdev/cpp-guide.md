
# Рекомендации по изучению C++

Этот документ не является учебным пособием по C++, но содержит рекомендации по быстрому обучению для разработчиков, готовых прочитать документы в этом каталоге.

Предполагается, что вы уже давно занимаетесь разработкой на C и знакомы с MCU, RTOS, драйверами, LVGL или аналогичными встроенными платформами; у вас должен быть большой опыт программирования, но вы можете быть не знакомы со знаниями C++, необходимыми для Glyphix.

::: совет
Если вашей целью является разработка собственных модулей, асинхронных функций или собственных виджетов, сначала прочтите эту статью, прежде чем продолжить чтение [Object System](./object-system.md) и других глав. Это позволит избежать многих проблем типа «вы можете понять код, но не можете его написать».
:::

## Подмножество возможностей C++

Проект Glyphix отключает некоторые функции C++, поэтому разработчикам вообще не нужно их изучать:

- Отключите **RTTI**: `dynamic_cast` и `typeid`, набор механизмов идентификации типов во время выполнения, использовать нельзя. Если требуется безопасное преобразование вниз, используйте напрямую [`dyn_cast`](object-system.md#dynamic type преобразование).
- Отключить **Исключения**: нет необходимости изучать `try`/`catch`/`throw` в качестве основного пути. Обработка ошибок отдает предпочтение возвращаемым значениям, кодам состояния, состояниям объектов и явным проверкам. Это похоже на привычки языка C по обработке ошибок.


Кроме того, среда выполнения Glyphix имеет некоторые особые ограничения, которые в основном вызваны ограничениями фрагментации и совместимости системы MCU:
1. Инструменты параллелизма стандартной библиотеки C++, такие как std::thread и std::mutex, недоступны в MCU.
2. Библиотеки времени, такие как `std::chrono`, также недоступны в MCU.
3. Не используйте статические локальные переменные (статические локальные функции). Атомарная инициализация гарантирована, поскольку C++11 **скорее всего, ненадежен** на MCU.
4. Не используйте глобальные переменные (объекты) с распределением в куче, поскольку фаза глобального построения на MCU может быть неконтролируемой и память в куче может быть недоступна.

Среди них 3 и 4 — очень распространенные ситуации, на которые следует обратить особое внимание.

## Требуется знание C++

Следующего содержимого достаточно для поддержки большинства документов в этом каталоге.

### Классы и объектно-ориентированное программирование

По крайней мере, вам нужно уметь читать и писать такой код:```cpp
class MyWidget : public Widget {
public:
    explicit MyWidget(Widget *parent = nullptr)
        : Widget(parent) {}

    void setValue(int value);
    int value() const;
};
```Вам необходимо понять:

- Разница между классами и структурами (небольшая разница, в основном права доступа по умолчанию)
- Значение публичного наследования (обычно используется только публичное наследование)
- Конструктор и список инициализации
- Функции-члены, **`const`-функции-члены**
- Когда переопределить интерфейс базового класса, а когда просто объявить обычную функцию-член

Эти знания появятся непосредственно в [Системе объектов](./object-system.md), [Руководстве по разработке элементов управления](./widget.md) и [Регистрации и экспорта элементов управления](./widget-export.md).

### Указатели, ссылки и `const`

Если вы знакомы с C, это самая простая часть «думать, что вы уже знаете», но использование C++ более строгое, чем использование C.

Пункты, которые необходимо по-настоящему освоить:

- Разница между `T*` и `T&`
- Когда передавать указатели и когда передавать ссылки
- Значение **`const T *`**, `T *const`, **`const T &`**
- Почему функции-члены `const` распространены
- Почему объекты не должны обрабатываться произвольно по байтам, как в C.

В Glyphix эти знания напрямую связаны с дизайном интерфейсов и безопасностью жизненного цикла.

### Жизненный цикл и управление ресурсами

Это самый важный раздел при переходе с C на C++.

Вам необходимо выработать такую привычку:

- Объекты автоматически уничтожаются, когда выходят за пределы области действия.
- Конструктор отвечает за установление допустимого состояния.
- Деструктор отвечает за освобождение ресурсов.
- Не ставьте «очистка ресурсов» в конце функции и не завершайте ее вручную.
— Не рассматривайте сложные объекты как обычные блоки памяти с помощью memset/memcpy.


Большое количество возможностей и функций Glyphix построено на модели жизненного цикла объектов C++, которая включает в себя такие темы, как RAII.

### Базовое использование шаблонов

Эта часть не требует глубокого понимания, но ее надо хотя бы уметь понимать:

- `Сигнал<int>`
- `Указатель<Метка>`
- `SharedRef<MyData>`
- `async::ResultSession<Client>`
- `std::vector<T>`

И знайте, что «шаблоны — это механизмы генерации кода с параметрами типа», а не какой-то продвинутый трюк, к которому прикасаются только авторы библиотек.

В документации Glyphix шаблоны в основном представлены в двух формах:

- **Общие типы контейнеров/инструментов**, например `Signal<T>`, `Pointer<T>`
- **Точки специализации**, например добавление `js_cast<T>` для пользовательских типов.

Разработчики должны, по крайней мере, понимать базовые термины, такие как «параметры шаблона», «создание экземпляра» и «специализация», а также уметь читать объявления и использовать типы шаблонов. Но не обязательно иметь возможность определять собственные шаблонные классы или функции.

### лямбда-выражение

В современном C++ лямбда — очень практичный способ написания одноразовых функций. Вы должны как минимум уметь читать:```cpp
mod["double"] = [](JsCtx ctx) -> JsValue {
    return ctx.arg(0).asInt(0) * 2;
};
```а также:```cpp
int factor = readScaleFactorFromConfig();
mod["scale"] = [factor](JsCtx ctx) -> JsValue {
    return ctx.arg(0).asInt(0) * factor;
};
```Во-первых, вы должны быть знакомы с базовым синтаксисом и механизмом захвата лямбда-выражений и сосредоточиться на понимании:

— лямбда — анонимный объект функции
- Лямбды без захвата часто можно использовать как обычные указатели на функции.
- Лямбда с захватом будет переносить состояние
- Когда лямбда-выражение сохраняется асинхронно, становится очень важно фиксировать время жизни объекта.

Это напрямую влияет на безопасность кода в [Разработка собственных модулей] (./native-module.md) и [Примеры асинхронной разработки] (./async-examples.md).

::: наконечник лямбды очень распространен
Лямбды фактически полностью занимают нишу функций обратного вызова, а значит, они повсюду. В некотором смысле лямбда-выражения, вероятно, являются наиболее важным моментом синтаксиса C++.

**Незахватываемые** лямбда-выражения почти идентичны указателям на функции C, за исключением того, что синтаксис отличается и может облегчить «трудность именования».
:::

### Минимальный рабочий набор стандартной библиотеки

Нет необходимости систематически изучать весь набор STL, но рекомендуется ознакомиться с этими наиболее распространенными компонентами:

- `std::vector`
- `std::array`
- `std::move`
- Базовые алгоритмы `<алгоритм>`, итераторы и диапазоны `for`

::: контейнер, связанный с наконечником
Glyphix имеет собственную реализацию HashMap и HashSet, которые очень похожи на std::unordered_map. Однако не рекомендуется использовать ассоциативные контейнеры, такие как `std::map`, `std::unordered_map`, поскольку их производительность низкая, а раздувание кода `std::map` очевидно.
:::

### Взаимодействие C и C++

Если вы хотите подключиться к базовому SDK, эта часть почти наверняка будет использоваться.

По крайней мере, вы должны быть в состоянии:

- Роль `внешнего "С"`
- Указатель функции обратного вызова C
- параметры контекста `void *` и неявные ограничения преобразования `void *` в C++.
- Разделение труда между структурами C и уровнями упаковки C++.

Вы увидите очень типичный шаблон в [Примерах асинхронной разработки](./async-examples.md): C API отвечает за истинное асинхронное выполнение, а уровень C++ выполняет только упаковку параметров, управление жизненным циклом и возврат результатов.

::: подсказка Ожидаемая сложность
Эта часть несложная, но при связывании легко допустить ошибки. Возможно, вам придется научиться решать различные проблемы, вызванные `extern "C"` при смешивании заголовочных файлов C/C++.
:::

## Рекомендуемая последовательность обучения

Рекомендуется выполнять их в следующем порядке, а не читать с первой страницы большого учебника.

### Сначала определите перспективу перехода «с C на C++»

[Часто задаваемые вопросы по ISO C++](https://isocpp.org/faq)
- Расставьте приоритеты по пунктам, связанным с «Изучение C++, если вы уже знаете C» и «Как сочетать C и C++».
- Этот контент подходит для опытных разработчиков C, поскольку предполагает, что вы уже понимаете память, интерфейсы, конструкцию и ограничения низкого уровня.

### Быстро создайте впечатление современного C++

[Экскурсия по C++](https://www.stroustrup.com/Tour.html)
- Если вы готовы согласиться на короткую книгу, то стоит инвестировать в нее.
- Это не «учебник по нулевому базовому программированию», а обзор современного C++ для опытных разработчиков.
- Цель не в том, чтобы запомнить их все, а в том, чтобы знать, каковы основные компоненты C++ и какие проблемы решает каждый.

### Руководство по синтаксису и запросам к стандартной библиотеке

[cppreference](https://en.cppreference.com/w/cpp)
- Подходит для проверки во время работы, не подходит для последовательного чтения.
- Если при чтении документации Glyphix вы встретите имена синтаксиса или библиотеки, такие как `override`, лямбда, список инициализации, специализация шаблона, `std::vector`, вы можете напрямую проверить это здесь.
- Если вам нужно просмотреть некоторые детали языка C, вы также можете найти их здесь.

### Переключитесь на современный C++

[Основные рекомендации C++](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)
— Это не учебник, а практическое руководство по инженерному делу, также доступное в опубликованной версии.
- Не рекомендуется читать полный текст по порядку; сначала прочтите эти главы:
  - `P`: общий принцип
  - `Я`: дизайн интерфейса
  - `F`: функция
  - `C`: классы и объекты
  - `R`: управление ресурсами
  - `ES`: выражения и утверждения
  - `CPL`: взаимодействие с C
  - `SF`: организация исходного файла.
  - `SL`: использование стандартной библиотеки.
  - `CP`: одновременное чтение по требованию.

[Статьи Embedded Artistry, посвященные C++](https://embeddedartistry.com/blog/tag/cpp/)
- Больше подходит для тематического чтения, а не для систематического курса.
- Темы, заслуживающие внимания, включают: как использовать C++ без кучи, строго типизированную инкапсуляцию регистров и что происходит в программе перед `main()`.

## Предложите, как использовать эти ресурсы

Более эффективный способ — не «немного изучать C++, а затем начать смотреть на Glyphix», а делать это параллельно:

1. Сначала внимательно прочтите эту статью, чтобы узнать, какие знания вам необходимо дополнить.
2. Прочтите [Экскурсию по C++](https://www.stroustrup.com/Tour.html) или FAQ, посвященный миграции на C.
3. Начните читать [Объектная система](./object-system.md) и [Разработка собственных модулей](./native-module.md).
4. Если вы столкнулись с синтаксисом, который вам не понятен, используйте [cppreference](https://en.cppreference.com/w/cpp) для точного запроса.
5. Если у вас возникнут такие вопросы, как «Почему современный C++ пишется именно так?», прочтите [Основные рекомендации по C++]. (https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines).

Такой темп обучения ближе к реальной работе и больше подходит для разработчиков, уже имеющих опыт внедрения.
