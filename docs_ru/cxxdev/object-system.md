
#Система объектов

Фреймворк C++ Glyphix имеет набор объектных моделей, основанных на PrimitiveObject, и понимание этого является основой для последующей разработки.

Объектная система состоит из трех взаимодействующих частей: **Система базовых классов объектов** определяет общие возможности и правила жизненного цикла всех управляемых объектов; **Система метаобъектов** генерирует метаданные для классов C++ с помощью компилятора метаобъектов во время создания, предоставляя им возможность отражения, привязки атрибутов и экспорта JavaScript; **Механизм безопасности памяти** решает распространенную проблему висячих указателей в средах графического пользовательского интерфейса с помощью защитных указателей и подсчета ссылок.

## Рефлексия и компилятор метаобъектов

Стандартные классы C++ «молчат»: как только вы получаете указатель на объект, вы не можете знать во время выполнения, какие у него есть члены, каковы их имена и как их читать и записывать. Это не является препятствием для статической разработки на C++, не требующей написания сценариев.

Но Glyphix работает по-другому. Когда шаблон страницы приложения записывает `:value="progress"`, адаптивная платформа должна найти соответствующее свойство элемента управления в соответствии со строкой `"value"` во время выполнения и автоматически обновлять при изменении данных. Эта способность «понимать свою собственную структуру во время работы программы» называется отражением и не поддерживается стандартом C++.

Решение Glyphix — добавить **Мета-компилятор** в процесс сборки. Он сканирует исходный код перед формальной компиляцией C++, генерируя метаданные для классов, которые должны участвовать в объектной системе. Разработчики просто помещают макрос **`GX_OBJECT`** в начало определения класса, и компилятор метаобъекта обрабатывает класс - затем платформа может читать и записывать его свойства или вызывать методы по имени и получать к нему доступ из JavaScript.

Вам пока не нужно понимать внутренность метаобъектной системы. Любой класс, для которого требуются возможности отражения, должен быть определен с помощью макроса GX_OBJECT и наследоваться от PrimitiveObject или Object.

## `PrimitiveObject` и `Object`

Объектная система-фреймворка разделена на два уровня:

**`PrimitiveObject`** — это корневой базовый класс для всех **управляемых объектов**. Следующие за ним классы обладают такими последствиями, как отражение атрибутов, динамическое преобразование и безопасное отложенное применение. это «объект C++ с поддерживающим фреймворком». Такие типы, как AsyncSession и BindableObject, унаследованы от него, поскольку этим классам не нужно формировать дерево.

**`Object`** наследуется от `PrimitiveObject` с дополнительной **родительско-дочерней древовидной структурой**: указатель `parent` объекта во время построения, и когда родительский объект уничтожается, все дочерние объекты также будут уничтожены рекурсивно. этот механизм.

::: аналогия с другими фреймворками
Glyphix с системой MOC Qt: `GX_OBJECT` соответствует `Q_OBJECT`. на два уровня; метаобъектов.

Другие платформы, такие как UCLASS от Unreal Engine, также имеют аналогичную систему отражения.
:::

Какой базовый класс вы выберете, зависит от того, должен ли ваш класс быть частью дерева:```cpp
// Необходимо участвовать в дереве объектов → наследовать объект
класс MySensor: общественный объект {
    GX_OBJECT
публика:
    явный MySensor(Object *parent = nullptr): Object(parent) {}
};

// С учетом только фреймов, не участвующих в дереве → Наследовать PrimitiveObject
класс MyNetworkSession: public PrimitiveObject {
    GX_OBJECT_KINDS(ExplicitDeleteKind)
публика:
    MyNetworkSession() = по умолчанию;
};
````GX_OBJECT_KINDS(ExplicitDeleteKind)` мета-объект подобного макроса `GX_OBJECT`, но сообщает платформа, что жизненный циклический объект этого объекта JavaScript. Его AsyncSession.

## Указатели защиты и безопасности памяти

В среде графического пользовательского интерфейса асинхронные сценарии могут легко вызвать любой другой указателя. Типичный случай:```cpp
void onNetworkResponse (const String &data) {
    //Сетевой запрос возвращается через 2 секунды
    // Но за эти 2 секунды пользователь мог выйти с текущей страницы и метка была уничтожена
    это-> метка-> setText (данные); // Ошибка сегментации!
}
```Все асинхронные сценарии, такие как обратные вызовы таймера и обратные вызовы ввода-вывода, имеют одинаковый риск. неизбежен, поэтому необходимо обеспечить безопасное наблюдение за механизмом в течение жизненного цикла.

### `Pointer<T>` охранный указатель

Глификс ПримитивныйОбъект. Используйте Pointer<T> для хранения перекрестных ссылок на объектах, не обращая внимания на собственность. При выключении объекта уничтожения автоматически обнуляется `Pointer<T>`, и его можно безопасно использовать, проверив перед разыменованием:```cpp
Указатель<Метка> m_label; //Объявлено как переменная-член

// ...назначение после построения...
m_label = метка;

// В любом асинхронном обратном вызове, который может привести к уничтожению метки:
void onNetworkResponse (const String &data) {
    если (!m_label)
        возврат; // метка уничтожена, безопасный выход
    m_label->setText(данные); // Доступ в настоящее время безопасен
}
```::: совет, при использовании
Сигнал Pointer<T>` также опирается на индикаторы указателей — когда получатель (в котором находится слот) отключается, соединение автоматически разрывается и никакие выходящие объектные обратные вызовы не возникают.
:::

::: лимит предупреждений
Указатели защиты не упоминают межпоточный доступ, они в основном ограничены потоком пользовательского интерфейса и не являются абстракцией с нулевыми издержками. включает конструкции в своей операции подсчета каналов связи.
:::

### `SharedRef<T>` Интрузивный подсчет ссылок

PrimitiveObject (например, структура данных), платформа обеспечивает навязчивый общий подсчет ссылок. значения назначают `SharedValue`, а затем с помощью `SharedRef<T>` для его хранения вы можете получить ссылку на этот вопрос. Это дополнительное выделение блока управления:```cpp
класс MyData: public SharedValue {
публика:
    интервал х = 0;
    Строковое имя;
};

auto ref1 = make_shared<MyData>();
ссылка1->х = 42;

SharedRef<MyData> ref2 = ref1; //Увеличиваем счетчик ссылок и делимся одним и тем же объектом
````SharedRef` также поддерживает копирование семантики при записи (COW): перед изменением скопированной версии создается независимая копия, чтобы определить, что несколько держателей не мешают друг другу. потоки безопасности.

## Динамическое преобразование типа

Стандартный C++ [`dynamic_cast`](https://en.cppreference.com/w/cpp/language/dynamic_cast) основан на RTTI (тип времени выполнения), в то время как встроенные среды обычно компилируются с `-fno-rtti`. `dyn_cast` обеспечивает эквивалентные сиспользования систем метаобъектов.

Целевой тип `T` для `dyn_cast<T *>()` должен соответствовать следующим условиям:
1. Унаследовано PrimitiveObject.
2. Объявлен макрос `GX_OBJECT`/`GX_OBJECT_KINDS`.```cpp
ПримитивныйОбъект *obj = getSomeObject();

// Безопасное преобразование вниз, если преобразование не удалось, вернуть nullptr
auto *btn = dyn_cast<Button *>(obj);
если(бтн)
    btn->setText("ОК");

// также поддерживается константная версия
const auto *constBtn = dyn_cast<const Button *>(obj);
```::: предупреждение `GX_OBJECT` соответствует условию
Проверка типа dyn_cast основана на информации статического метаобъекта («staticMetaObject») целевого класса. Включенный класс не объявляет `GX_OBJECT`, необходимый тип времени выполнения отсутствует и вызывает ошибку компиляции.
:::

`dyn_cast`: платформа часто передает объекты в качестве указателей базового класса (`PrimitiveObject *` или `Object *`), `dyn_cast` необходим для безопасного восстановления их в соответствии с определенными типами перед работой.

Учитывая, что политика безопасности песочницы не доверяет объекту, переданному сценарием, мы не можем предполагать, что переданный указатель объекта времени выполнения имеет правильный тип, поэтому необходимо использовать `dyn_cast` для проверки типа и безопасного доступа к его организатору.

### Ловушка уничтожения памяти

Типичные шаблоны использования dyn_cast указывают на риск утечки памяти, например:```cpp
auto *session = dyn_cast<Session *>(takeObjectOwnership());
если (сеанс) {
    // Успешное преобразование, доступ к членам сессии и передача владения
}
```Проблема в том, что если объект, возвращаемый режим takeObjectOwnership(), не относится к типу Session, dyn_cast вернет nullptr, но право собственности на исходный объект было передано, что приводит к потере памяти, если нет другого механизма для повторного использования объекта.

При разработке API собственного модуля вы иногда сталкиваетесь с этой проблемой, и связанная с ней платформа предоставляет лучший API-интерфейс, чтобы избежать ситуаций. dyn_cast.

- Нет необходимости использовать JavaScript

### Отражение сложного типа

Для классов, объявленных с помощью GX_OBJECT, GX_ENUM и GX_STRUCT, также можно использовать для экспорта типов элементы перечисления и структуры, чтобы их можно было также использовать в JavaScript. код привязки.

#### Отражение перечисления `GX_ENUM`

Когда типом свойства или метода является перечисление C++, представление его непосредственно в JavaScript, поскольку значение числа является неинтуитивным и ошибочным. `GX_ENUM` экспортирует JavaScript для работы с удобочитаемыми строками вместо магических чисел:```cpp
класс ScrollArea: публичный виджет {
    GX_OBJECT
публика:
    перечисление GX_ENUM ScrollBarStyle {
        RemoveScrollBar GX_ALIAS («скрыт»),
        LinearScrollBar GX_ALIAS («линия»),
        DotsScrollBar GX_ALIAS («точки»)
    };

    GX_PROPERTY (индикатор ScrollBarStyle, установите setScrollBar)
};
````GX_ENUM` JavaScript, для каждого зывается исходное имя члена C++. Разработчики приложений используют JavaScript следующим образом:```js
Scroll.indicator = "скрытый"; // Соответствует RemoveScrollBar
прокрутка.индикатор = "точки"; // Соответствует DotsScrollBar
```Когда платформа считывает атрибут «indicator», она преобразует символ «dots» в значение перечисления «DotsScrollBar», а затем передает ее установщику; букв. такими перечислениями.

#### Отражение параметра структуры `GX_STRUCT`

Для параметров метода иногда требуется описание нескольких разделов. GX_STRUCT, чтобы сторона JavaScript могла передать буквальный объект:```cpp
класс Scroll: public ScrollArea {
    GX_OBJECT
публика:
    struct GX_STRUCT ScrollOptions {
        Длина слева;
        Длина верха;
        Поведение ScrollBehavior;
    };
    struct GX_STRUCT IndexOptions {
        внутренний индекс;
        Поведение ScrollBehavior;
    };

    GX_METHOD void ScrollTo(const ScrollOptions &options);
    GX_METHOD void ScrollBy(const ScrollOptions &options);
    GX_METHOD void setIndex(const IndexOptions &options);
};
````GX_STRUCT` размещается после ключевого слова `struct`, и каждая структура автоматически экспортируется в соответствии с его типом (также посредством встроенного построения типа или вложенного `GX_ENUM`).```js
Scroll.scrollTo({ слева: 0, сверху: 200, поведение: «гладкое» });
Scroll.setIndex({индекс: 3, поведение: "мгновенный" });
```ScrollTo` ScrollTo` на стороне C++, всегда является строго типизированным объектом `ScrollOptions` без какого-либо анализа на стороне C++.

::: предупреждение Не забудьте отметить
При объявлении GX_PROPERTY перечислением или структурой обязательно правильно использовать рекомендации GX_ENUM или GX_STRUCT. использовать эти свойства или методы, и сообщение об их отсутствии.
:::

### Существует ли «промежуточное представление»?

При использовании Variant для соединений C++ и JavaScript объекты JavaScript преобразуются в общее промежуточное представление, например, в некоторую JSON-подобную структуру сериализации?

Ответ — нет. информация о типе и семантике операций объекта. Вариант без необходимости использования специального промежуточного представления или процесса сериализации.
