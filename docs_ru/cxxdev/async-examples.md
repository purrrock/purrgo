
# Пример асинхронной разработки

Если вы считаете, что [Разработка асинхронных функций] (async.md) недостаточно понятна, в этом документе представлены некоторые типичные и более простые примеры, которые помогают вам справиться с некоторыми распространенными сценариями асинхронной разработки.

Эти сценарии не очень сложны, но состоят из:
- Типичный шаблон асинхронных вызовов, ориентированный на межпотоковые и межъязыковые вызовы;
— Эти сценарии могут быть более тривиальными, существует большое количество системных API, которые необходимо подключить, и они более чувствительны к расширению кода;
— определить типичные требования к взаимодействию с C API, а не стандартным интерфейсом C++.

Вы можете найти полные реализации этих действий в примерах SDK и запустить их прямо на своем ПК.

### Базовый режим привязки

«alarm.create()» в примере, чтобы показать полный процесс привязки:```cpp
static JsValue jsAlarmCreate(JsCtx ctx) {
    auto *applet = Applet::current(ctx.vm());
    if (!applet || ctx.argc() < 1 || !ctx.arg(0).isObject())
        вернуть JsValue{};

    //Читаем параметры из объекта параметров, переданного из JavaScript
    const JsValue &opts = ctx.arg(0);
    uint32_t интервалMs = static_cast<uint32_t>(opts["interval"].toInt());
    Строковая метка = opts["метка"].toString();
    Alarm_repeat_t маска = parseRepeatMask(opts["repeat"]);

    // Создаем сеанс и извлекаем обратные вызовы разрешения/отклонения из объекта параметров (поддерживает два асинхронных стиля)
    auto *session = async::make<AlarmSession>(апплет);
    сеанс->setResolver(opts);

    // Обратный вызов C: вызывается в рабочем потоке, уведомляет JavaScript между потоками черезsolve()
    auto Done = +[](alarm_err_t err, Alarm_id_t id, void *data) {
        auto *s = static_cast<AlarmSession *>(данные);
        s->resolve(err == ALARM_OK
            ? async::Result<int>(id) // Успех: разрешить вновь созданный идентификатор будильника
            : async::Status(err)); // Ошибка: отклонить, сообщение об ошибке поступает из errorMessage()
    };

    // Вызов интерфейса создания асинхронного будильника службы C, передавая обратный вызов и указатель сеанса
    Alarm_async_create(AppletAlarmService::instance(),
                       интервалMs, маска, label.c_str(), /*...*/,
                       onAlarmFired, nullptr, готово, сеанс);
    // Возвращаем объект Promise в JavaScript, фреймворк автоматически разрешит его при вызове методаsolve()
    вернуть сеанс->обещание();
}
```Вот несколько фиксированных процедур, которые можно скопировать и использовать напрямую:

- `async::make<AlarmSession>(applet)` требования жизненного цикла.
- `session->setResolver(opts)` асинхронные вызовы [стиль обратного вызова и стиль обещания] (/api/README.md#Quick Application Asynchronous Interface).
- `+[](... void *data)` удовлетворяет требованиям типа для обратных вызовов C.
- Передайте `session` как `void *` C API `resolve()`.
- `resolve()` является потокобезопасным. Обещать.

#### JavaScript

Интуитивно кажется разумным, чтобы приложение передало функцию обратного вызова при регистрации сигнала звука:```Javascript
// ❌ Это не работает в сценарии будильника.
Alarm.create({ интервал: 60000, onFired: (событие) => { /* ... */ } })
```Проблема в том, что сигналы излучателя поглощают жизненный цикл приложения: после создания как сигнал, так и сдача сигнала после перезапуска.

JavaScript JavaScript («JsValue») JavaScript JavaScript экземпляра приложения. всем JsValue. говоря уже о том, чтобы вызвать его при организации сигнализации.

Это проблема не только будильников. JavaScript**, решено с обратными вызовами JavaScript**, решено задачи, отправка автономных сообщений, уведомлений о завершении фоновой загрузки и т. д. д.

#### Используйте методы согласованных имен вместо ссылок на обратный вызов

Самое простое решение: вместо того, чтобы приложение «регистрировало обратный вызов», система активно **запускает** приложение при возникновении событий и выдает метод обработки объекта приложения с методом согласованного имени.

Это соответствует идее функций жизненного цикла приложения («onCreate», «onShow» и т. д.) — система запускает приложение в программе и вызывает другие методы ввода вместо сохранения заранее зарегистрированных обратных вызовов. согласно соглашению:```Javascript
// app.js — методы обработки, экспортируемые объектами модели приложения (реализовано по соглашению)
экспортировать по умолчанию {
  onAlarmFired (событие) {
    // событие: { id, метка, интервал, ... }
    console.log('сработала сигнализация:', событие)
  }
}
```Реализация на стороне C++: сначала прочитайте снимок в рабочем потоке, затем переключитесь обратно в основной поток, чтобы запустить приложение и вызвать метод:```cpp
static void onAlarmFired(alarm_id_t id, void * /*user_data*/) {
    //Читаем снимок в рабочем потоке, чтобы избежать перекрестного доступа к таблице будильников
    Alarm_info_t информация {};
    Alarm_get_info (идентификатор, & информация);

    // Переключаемся обратно в основной поток и затем работаем с JavaScript
    App()->postTask([информация] {
        auto *svc = AppletAlarmService::instance();
        // Используйте launch() для запуска (или пробуждения) целевого приложения, даже если оно в данный момент не запущено
        auto *applet = AppletKit::instance()->launch(svc->alarmAppletName);
        if (!applet) return;

авто &vm = JsVM::current();
        //Вызов согласованного метода для экспортированного объекта app.js, а параметром события является объект JavaScript информации о будильнике.
        Событие JsValue = js_cast (информация);
        applet->modelObject().callMethod("onAlarmFired", {event}).reportError();
    });
}
```Несколько ключевых моментов:

- **Не** напрямую манипулируйте JsValue и не вызывайте какой-либо API JavaScript в рабочем потоке, их можно использовать только в потоке пользовательского интерфейса.
- Используйте `App()->postTask()`, чтобы доставить замыкание в события основного цикла для выполнения. Это самый простой способ вернуться к основному потоку.
- Используйте AppletKit::launch() вместо замены существующего экземпляра; `launch()` перезапустите приложение, если оно не существует, или вернет существующий экземпляр, если приложение уже запущено.
- `.reportError()` по возвращаемому результату `callMethod()` будет печатать возможности включения JavaScript в журнале, а не сопровождать их автоматически.

::: подсказка Обычные имена методов — это самый простой способ обработки событий.
Этот шаблон можно понимать так: экспортированный объект app.js — это «коллекция точек входа», предоставляемая приложениям системы. точно так же, как вызовы onCreate и onShow.

Этот метод не является очень универсальным, но в принципе достаточен для управляемых системных приложений, он прост в реализации и не требует сложных критериев управления сохранением и обратными вызовами.
:::

### Регистрация загрузчика библиотеки

После того, как все функции привязки написаны, их необходимо «собрать» в [объект библиотеки] (native-module.md#library-loader), JavaScript и зарегистрировать в фреймворке.

Загрузчик библиотеки — это функция C++, которая запускается, когда приложение вызывает app.loadLibrary('vendor.alarm')` JavaScript, JavaScript, JavaScript:```cpp
static JsValue libAlarmLoader(Applet *applet) {
    // Здесь вы можете проверить имя пакета приложения, чтобы запретить несанкционированный доступ к приложению. Поля также можно проверить.
    if (!applet || applet->objectName() != "com.vendor.alarm")
        вернуть JsValue{};

    JsValue lib = JsVM::current().newObject();

    // Монтируем функцию привязки к объекту библиотеки. Имя атрибута — это имя метода, вызываемого на стороне JavaScript.
    lib["create"] = jsAlarmCreate;
    lib["отмена"] = jsAlarmCancel;
    lib["список"] = jsAlarmList;
    lib["count"] = jsAlarmCount;
    // ...
    вернуть библиотеку;
}
```Затем зарегистрируйте загрузчик с помощью AppletKit на основных основах:```cpp
Комплект AppletKit{&window};
kit.setLibraryLoader("vendor.alarm", libAlarmLoader);
```Сторона JavaScript импортируется через app.loadLibrary(), возвращаемое значение — это объект библиотеки, возвращаемый загрузчиком:```Javascript
