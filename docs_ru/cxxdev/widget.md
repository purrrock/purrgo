# Руководство по разработке элементов управления

В Glyphix все видимые элементы пользовательского интерфейса являются виджетами. Платформа имеет встроенные общие элементы управления, такие как кнопки, метки, изображения и области прокрутки, но производителям оборудования часто приходится разрабатывать индивидуальные элементы управления на основе особенностей своего продукта. Например, для умных часов может потребоваться специальная анимация списков из-за их меньших круглых экранов, а для приборов-инструментов могут потребоваться индивидуальные элементы управления диаграммой. В этом документе описывается, как реализовать новый элемент управления на C++.

## Основы управления

«Виджет» представляет собой прямоугольную область. Он имеет базовые свойства, такие как положение, размер, видимость, прозрачность и т. д. Он может получать события и отвечает за отрисовку собственного контента. Элементы управления организованы в древовидную структуру: родительский элемент управления содержит несколько дочерних элементов управления, а координаты дочерних элементов управления относятся к родительскому элементу управления.

Каждый элемент управления имеет **логический цикл обновления**: когда состояние элемента управления изменяется (например, обновляются данные), вызывается `update()`, чтобы пометить его как «требующее перерисовки», и платформа равномерно перерисует все отмеченные элементы управления в следующем кадре рендеринга вместо немедленной перерисовки — это позволяет избежать многократного повторения отрисовки в одном и том же кадре.

### Система управления и компонентов

Элементы управления пользовательского интерфейса обычно реализуются как класс C++, наследуемый от Widget и соответствующий стандартному объектно-ориентированному дизайну C++. Реактивная структура и система компонентов Glyphix поддерживают прямое представление этих элементов управления C++ как собственных компонентов и использование их в шаблонном и декларативном виде.

Такая конструкция делает разработку элементов управления на стороне C++ и использование внешних компонентов относительно независимыми, а также поддерживает методы разработки, используемые обеими сторонами. Например, в C++ вы можете создавать интерфейсы наподобие LVGL или Qt Widgets, не принимая при этом декларативный стиль, популярный во внешних платформах.

### Сравнение с другими фреймворками

Система управления Glyphix по конструкции аналогична традиционным средам пользовательского интерфейса C/C++, таким как Qt Widgets или LVGL. Таким образом, вы обнаружите, что способ и система знаний для разработки нового элемента управления очень похожи на эти структуры:
— Создать новый класс управления, унаследовав «Виджет»;
- Существуют основные механизмы, такие как система макетов, система событий и система рисования;
- Реализация привязки данных и уведомления о событиях через систему атрибутов и механизм сигналов;
- Он имеет геометрические концепции, такие как система координат и размер, и поддерживает вложенную древовидную структуру управления.

::: совет Не рекомендуется использовать элементы управления C++ для разработки пользовательского интерфейса.
Glyphix не предназначен для разработки пользовательского интерфейса непосредственно на стороне C++, поэтому мы не будем предоставлять соответствующую документацию и примеры.
:::

### Определить класс управления

Создайте новый элемент управления, унаследуйте Widget, добавьте макрос GX_OBJECT в начале определения класса и переопределите виртуальную функцию event()** в качестве точки входа для обработки событий:```cpp
// progressring.h
#include "gx_widget.h"

class ProgressRing : public Widget {
    GX_OBJECT
public:
    explicit ProgressRing(Widget *parent = nullptr)
        : Widget(parent), m_value(0) {}

    int value() const { return m_value; }
    void setValue(int v);
    bool event(Event *event) override;

    GX_PROPERTY(int value, get value, set setValue, signal valueChanged)
    Signal<int> valueChanged;

protected:
    void paintEvent(PaintEvent *event);

    // EventDispatch 需要访问 protected 方法，声明友元
    friend struct EventTraits<ProgressRing>;

private:
    int m_value;  // [0, 100]
};
````GX_OBJECT` имеет важное значение, он заставляет компилятор мета-объекта генерировать метаданные для этого класса, чтобы элемент управления мог правильно восприниматься системой свойств платформы, системой анимации и системой компонентов (подробности см. в [Object System](./object-system.md)).

### Элементы управления рисованием

Включите gx_widgetevent.h в файл .cpp, реализуя event() иpaintEvent():```cpp
// progressring.cpp
#include "progressring.h"
#include "gx_widgetevent.h"

bool ProgressRing::event(Event *event) {
    return EventDispatch<Widget>{}(this, event);
}

void ProgressRing::paintEvent(PaintEvent *event) {
    Widget::paintEvent(event);
    Painter p(this);
    // ... 详见绘制章节
}
```Пользовательское рисование завершается реализацией `paintEvent()`; при создании Painter передайте указатель this, чтобы получить контекст рисования, связанный с текущим элементом управления, а затем вызовите различные методы рисования для рисования. Полное описание API Painter см. в главе [Painting](./painting.md).

### Обработка событий

Система событий Glyphix **не полагается на наследование виртуальных функций** для распространения событий. `paintEvent()`, `gestureEvent()` и другие методы не являются `виртуальными`. **Не** добавляйте `override` при их объявлении (будет сообщено об ошибках компиляции). Платформа маршрутизирует вызовы к правильной функции-обработчику по типу события во время компиляции через EventDispatch.

Единственная виртуальная функция, которую необходимо (и необходимо) переопределить, — это **`event()`**, где она делегирует `EventDispatch`:```cpp
bool ProgressRing::event(Event *event) {
    return EventDispatch<Widget>{}(this, event);
}
```Первым параметром шаблона EventDispatch обычно является **прямой базовый класс** (то есть класс, от которого наследуется `ProgressRing`, в данном случае `Widget`). Во время компиляции он проверит, объявляет ли текущий класс напрямую соответствующую функцию обработки, и если да, то вызовет ее, в противном случае он автоматически вернется к реализации базового класса. Когда возвращаемое значение функции-обработчика равно bool, это указывает, было ли событие использовано; когда он возвращает «void», считается, что он был израсходован.

::: совет Советы по выбору базового класса
Существует несколько методов оптимизации выбора параметра базового класса EventDispatch. Обычно вы можете выбрать прямой базовый класс, но вы также можете использовать класс-предок более высокого уровня, что приведет к незначительным различиям в размере кода и производительности. Но в целом не стоит слишком запутываться и не стоит беспокоиться о неправильном использовании и ошибках — пока компиляция пройдет, распределение событий будет работать корректно.
:::

::: важно
Когда ниже упоминается термин «переопределение `xxxEvent()`», обратите внимание, что в производном классе управления объявляется только функция-член с той же сигнатурой, что и функция обработки событий базового класса, но **невиртуальная**. Это не виртуальная функция, ее нельзя переопределить, и она не использует механизм виртуальных функций для распространения событий.

IDE может предложить вам изменить эти функции-члены на виртуальные функции, но игнорируйте это приглашение.
:::

Если вы хотите обрабатывать ввод жестами, объявите «gestureEvent()» и реализуйте его в своем классе:```cpp
//Добавляем оператор в защищенную область заголовочного файла:
bool жестEvent(GestureEvent *event);

// Реализовано в .cpp:
bool ProgressRing::gestureEvent(GestureEvent *event) {
    if (event->type() == Event::Press) {
        // ...
        вернуть истину; // Возврат true означает, что событие было использовано и больше не будет передаваться родительскому элементу управления.
    }
    вернуть ложь;
}
```Типы событий, которые можно обработать:

| Сигнатурный метод | Время разработки |
|---|---|
| `bool жестEvent(GestureEvent *)` |
| `boolwheelEvent(WheelEvent *)` | Ввод колесика или ручки (например, заводные головные часы) |
| `bool keyEvent(KeyEvent *)` | Ключ сущности |
| `void resizeEvent(ResizeEvent *)` | Изменение размера управления |
| `void moveEvent(MoveEvent *)` | Изменения положений управления |
| `bool focusEvent(FocusEvent *)` | Изменение фокуса |
| `voidpaintEvent(PaintEvent *)` | Запрос на перерисовку |
| `boollayoutEvent(LayoutEvent *)` | Запрос на макет |
| `voidtickEvent(TickEvent *)` |

Если функции обработки событий **должны быть реализованы** для каждого элемента.```cpp
bool MyButton::event(Событие *event) {
    // Если краскаEvent или жестEvent объявлены неправильно, компиляция не удалась
    return EventDispatch<Widget, PaintEvent, GestureEvent>{}(this, event);
}
```::: подсказка объявляет об обеспечении функций обработки событий
EventDispatch<Widget>` можно использовать для автоматического распространения всех событий, **настоятельно рекомендуется** явно объявлять типы событий, которые должны обрабатывать текущий элемент управления, чтобы можно было как можно больше проверять упущения или технические ошибки во время компиляции и снижать нагрузку на проверку вручную.
:::

### Свойства сигналов

Используйте макрос GX_PROPERTY, чтобы рассчитать свойства платформы, чтобы их можно было связать с уровнем приложения, а также использовать в качестве целей для свойства анимации:```cpp
// Объявляем атрибут value, метод получения — value(), метод установки — setValue()
// Поле сигнала связано с сигналом изменения, на который может подписаться адаптивная платформа.
GX_PROPERTY(целое значение, получить значение, установить setValue, значение сигналаChanged)
```После объявления значение атрибута может:
- Непосредственно применять шаблоны уровней приложений (например, `<progress-ring :value="progress"/>`)
- Плавные переходы с помощью системы анимации (интерполяции)

Вызовите update() в установщике, чтобы запустить перерисовку и отправить сигнал ожидаемого значения в ближайшее время:```cpp
void ProgressRing::setValue(int v) {
    если (m_value == v) возврат;
    m_value = v;
    обновлять(); // Отмечаем следующий кадр для перерисовки
    значениеИзменено (в); // излучаем сигнал
}
````Signal<T>` — Signal<T> Используйте Signal<>` для сигналов без параметров и не передавайте параметры при вызове. (./объект-система.md).

## Рисовать

### Начало реализации

Создайте Painter в функции-члене PaintEvent() элемента управления, чтобы начать рисование:```cpp
void ProgressRing::paintEvent(PaintEvent *event) {
    Художник p(это);
    // Все последующее рисование завершается через p
}
```в качестве начальной координаты, $+x$ справа, $+y$ внизу, единица измерения — пиксели. `rect()` возвращает локальный код `(0, 0, width(), height())` текущий элемент управления, который является наиболее часто используемой ссылочной областью при рисовании.

Если элемент управления имеет свойства стиля, управляемые рамки, такие как цвет фона, StyleModifier, вы можете вызвать базовый класс для обработки этих фонов перед рисованием пользовательского изменения:```cpp
void ProgressRing::paintEvent(PaintEvent *event) {
    Виджет::paintEvent(событие); // Сначала рисуем фон, управляемый фреймом (если есть)
    Художник p(это);
    // ...
}
```Когда базовый класс не возникает, стиль фонаря, управляемый платформой, будет для всех визуальных представлений с помощью собственного PaintEvent.

### Статус чертежа

Состояние «Художник» до этой модификации.

#### Кость

Кость определяет методы класса заливки («fillRect», «fillRoundedRect», «fillPath» и т. д.) и цвет, динамический для текста:```cpp
p.setBrush(Color(200, 200, 200)); // RGB серый
p.setBrush(Color{"#35a7ff"}); // Шестнадцатеричная строка
p.setBrush(Цвет::Белый); // Предопределенные константы
p.setBrush(Color(0xff4486ff)); // Шестнадцатеричное целое число ARGB (0xff полностью непрозрачно)
```#### Ручка

Обводка («drawRect», «drawArc», «drawLine» и т. д.):```cpp
Ручка-ручка(Цвет(64, 156, 255));
pen.setSize(6); // Ширина линии 6 пикселей
p.setPen(ручка);
```#### Другой статус```cpp
p.setFont(Шрифт(18)); // Размер шрифта 18 пикселей, влияет на функцию drawText()
p.setOpacity(127); // Прозрачность [0, 255], влияющая на все последующие рисунки
```Все состояние проявляется только на нынешнем примере Художник, художник, созданный с помощью разных элементов управления, полностью независимый и не мешающий друг другу.

### Базовая форма

#### Прямоугольник```cpp
p.setBrush(Цвет::Белый);
p.fillRect(прямо()); // Заполняем всю область управления
p.fillRect(Rect(10, 10, 60, 20)); // Заполняем указанный прямоугольник

p.fillRoundedRect(rect(), 8.0f); // Заливка закругленных углов, радиус угла 8 пикселей
p.drawRoundedRect(rect(), 8.0f); // Закругленная обводка (без заливки, используйте цвет пера)
```Когда угол наклона сзади меньшего значения и высоты, обратите внимание на форму капсулы, что очень часто встречается в кнопках и индикаторах выполнения:```cpp
float radius = min(box.width(), box.height()) * 0,5f;
p.fillRoundedRect(коробка, радиус);
```#### Прямая линия```cpp
p.drawLine(Point(0, cy), Point(width(), cy)); // Горизонтальная разделительная линия
```#### Арка

`drawArc` задает дугу с центральными координатами и радиусом, `startAngle`/`endAngle` переход в градусах, $0°$ соответствует направлению $3$ часов, увеличиваясь по часовой стрелке:```cpp
поплавок cx = ширина () / 2.0f;
поплавок cy = высота () / 2.0f;
радиус плавания = min(cx, cy) - 4.0f;

// Рисуем полную дугу (фоновое кольцо), проходящую от -90° (12 часов)
Pen bgPen(Color(200, 200, 200));
bgPen.setWidth(6);
p.setPen(bgPen);
p.drawArc({cx, cy}, radius, -90.0f, -90.0f + 360.0f);

//Рисуем дугу прогресса (по часовой стрелке от 12 часов до соответствующей позиции прогресса)
если (m_value > 0) {
    Перо fgPen(Цвет(64, 156, 255));
    fgPen.setWidth(6);
    p.setPen(fgPen);
    p.drawArc({cx, cy}, radius, -90.0f, -90.0f + 360.0f * m_value / 100.0f);
}
```Визуальная защита дуги постоянной линии «Пена».

### Векторный путь `VectorPath`

VectorPath для FillPath() и drawPath().```cpp
#include "gx_vectorpath.h"
```VectorPath работает как «траектория кисти»: воспользуйтесь moveTo для записей сегментов прямых линий lineTo, сегментов Painter.

#### Путь отрезок прямой линии```cpp
Путь ВекторПат;
path.moveTo(x0, y0); // Положим перо на бумагу (без рисования)
path.lineTo(x1, y1); // Прямая линия до (x1, y1)
path.lineTo(x2, y2);
path.lineTo(x0, y0); // Возвращаемся в начальную точку для формирования замкнутого треугольника

p.fillPath(путь, Color(64, 156, 255)); // Заполняем замкнутую область
````fillPath()` таким образом в начальной точке. `drawPath()` использует `Pen` для рисования контура пути без его заполнения.

#### Путь сегмента дуги

Параметры `arcTo` — это центр круга, радиус $x/y$ (для эллипсов они не являются обязательными), начальный угол и угол поворота (система угла, по часовой стрелке положительно):```cpp
//Рисуем горизонтальную форму капсулы: левый полукруг + правый полукруг, arcTo автоматически соединяет два сегмента соединительной линией
float r = rect.height() * 0,5f;
float x1 = rect.left() + r;
float x2 = rect.right() - r;
поплавок y = rect.top() + r;

Путь ВекторПат;
path.arcTo(PointF(x1, y), r, r, 90.0f, 270.0f); // Левый крайний полукруг (против часовой стрелки от 9 часов до 3 часов)
path.arcTo(PointF(x2, y), r, r, -90.0f, 90.0f); // Правый крайний полукруг (против часовой стрелки от 3 часов до 9 часов)
p.fillPath(путь);
````arcTo` автоматически вставляет прямую линию между текущей конечной точкой пути и начальной точкой новой дуги, поэтому две дуги последовательно соединяются таким образом, начиная с начала до конца, без необходимости дополнительных вызовов `lineTo`.

#### Кривая

Используйте `conicTo` или `cubicTo` для построения квадратичных или кубических сегментов изогнутой формы и используйте `moveTo` и `lineTo` для описания сложных контуров:```cpp
Путь ВекторПат;
path.moveTo(x0, y0);
// Квадратичная кривая Безье, (cx, cy) — контрольная точка
path.conicTo(cx, cy, x1, y1);
// Кубическая кривая Безье, (cx1, cy1) и (cx2, cy2) — контрольные точки

// Заполняем путь указанной кистью

## AbstractScrollArea и элементы управления с обеспечением прокрутки

Если элемент управления требует поведения прокрутки, нет необходимости реализовывать распознавание жестов, инерционную прокрутку и эффекты отскока с нуля. направить AbstractScrollArea, чтобы получить эти возможности. Фрейворк «ScrollArea» (прокрутка списка) и «TextField» (однострочный ввод текста).

### Базовая структура

AbstractScrollArea, «Элементы управления, следующее просмотрение», внутри находится виджет контента, который отвечает за перенос фактического контента.

Инициализация завершается в конструкторе:```cpp

    GX_OBJECT

    явный MyTicker(Widget *parent = nullptr);
    bool event(Событие *event) переопределить;

    boollayoutEvent(LayoutEvent *event);
    друг struct EventTraits<MyTicker>;
};
``````cpp
// myticker.cpp

#include "gx_widgetevent.h"

MyTicker::MyTicker(Widget *parent) : AbstractScrollArea(parent) {
    setDirection (по горизонтали); // Горизонтальная прокрутка
    setDamping (5); //Настраиваем демпфирование (чем больше значение, тем сильнее трение)

    авто *content = новый виджет; // Создаем элемент управления контентом
    setContentWidget (содержание);

}
```Установка параметра базового класса EventDispatch значения AbstractScrollArea (вместо виджета) Позволяет событиям (жестам, колесам прокрутки, определению размера и т. д.), которые не обрабатываются текущим классом, автоматически начинаются реализации AbstractScrollArea, сохраняя таким образом полное выполнение прокрутки.

### Настройка параметров прокрутки```cpp
setDirection (Вертикально); // Вертикальная прокрутка (по умолчанию)
setDirection (по горизонтали); // Горизонтальная прокрутка
setDamping (3); // Меньшее демпфирование: более сильная инерция, скольжение дальше
установитьДемпинг (20); //Более высокое демпфирование: слабая инерция, инерция почти отсутствует
setScrollBar (истина); //Показать полосу прокрутки

```«AbstractScrollArea» также обеспечивает «scrollTo(x, y, Behavior)» для программного управления положениями прокрутки, а «поведение» — «Мгновенный» (немедленный переход) или «Плавный» (с анимацией).

::: инерционное демпфирование наконечника
Для таких элементов управления, как TextField, которые требуют точного контроля положения прокрутки, обычно задается более высокое значение демпфирования, чтобы ослабить инерцию; В то время как для таких элементов управления, как «ScrollArea», которые в основном ориентированы на просмотр, вы можете установить более низкое значение демпфирования, чтобы получить более плавную прокрутку.

Не устанавливайте слишком низкое демпфирование, иначе прокрутка на больших расстояниях может привести к сбою кэша контента и зависимости.
:::
