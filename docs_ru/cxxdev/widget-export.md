
# Управление регистрацией и интеграцией фреймворка

В [Руководстве по разработке элементов управления](./widget.md) мы реализовали класс элемента управления C++. Но на данный момент это всего лишь обычный объект C++, и разработчики приложений не могут использовать его непосредственно в коде страницы. В этой статье описывается, как зарегистрировать элемент управления в платформе, чтобы он стал компонентом, который можно использовать в вашем приложении. Многие понятия в этом документе связаны с [Object System](./object-system.md). Рекомендуется сначала прочитать соответствующий контент.

## Рабочая среда

Регистрация элементов управления основана на наборе **объектов рабочей среды**. Это необходимые зависимости для запуска реактивной среды. Они должны быть явно созданы в `main()` или коде запуска платформы, а их жизненный цикл должен охватывать весь период работы приложения:```cpp
Application app(/* platform */);
JsVM vm;
Window window;
AppletKit kit(&window, "pkgs.db");
```Эти объекты отвечают за рабочую среду всего приложения:
- Объект приложения платформы Application отвечает за все базовые службы и поддержание цикла событий. В конце инициализации вызовите app.exec(), чтобы войти в цикл обработки событий;
- `JsVM` — это встроенный движок JavaScript, на котором работает адаптивная платформа, и его необходимо создать до `AppletKit`;
- «Окно» — окно верхнего уровня, используемое в качестве цели вывода рендеринга;
- `AppletKit` — менеджер приложений (Applet), отвечающий за жизненный цикл приложения и управляющий регистрацией.

::: предупреждение: не пропускайте эти объекты
`vm`, `window`, `kit` и т. д. являются объектами RAII, и фреймворк управляет рабочей средой посредством их создания/уничтожения. Даже если вы не видите прямого вызова `vm` в коде, требуется само его существование - преждевременное его уничтожение или отказ от создания приведет к тому, что фреймворк не будет работать.
:::

«Окно» иногда можно заменить на «Окно виджета» и т. д. Разница в том, что «Окно» по умолчанию рисует непрозрачный фон, а «Виджет» по умолчанию рисует прозрачный фон.

## Регистрация управления

Регистрация элемента управления выполняется через `AppletKit::installWidget<T>()`, который вызывается после создания экземпляра `AppletKit` и до того, как `launch()` запускает первое приложение:```cpp
// 注册自定义控件（在 launch 之前）
kit.installWidget<ProgressRing>(); // 无参数，以类名注册，模板中写作 <progress-ring>
kit.installWidget<MySpecialChart>("SpecialChart"); // 或用自定义名称注册（见下文）

kit.launch("com.example.app");     // 启动应用
return app.exec();                 // 进入事件循环
```::: подсказка Встроенные элементы управления регистрируются по умолчанию
Встроенные элементы управления, такие как кнопки и метки, поставляемые с платформой, регистрируются с помощью `installBuiltinWidgets()`. Пока SDK собран с включенной опцией CMake GX_BUILTIN_BINDINGS (по умолчанию ON), он будет вызываться автоматически при создании AppletKit без ручной обработки. Вам нужно будет вызвать kit.installBuiltinWidgets() самостоятельно только в том случае, если вы явно отключите эту опцию.
:::

После регистрации платформа автоматически экспортирует свои свойства, события, методы, а также типы перечислений и структур, которые они используют, на основе метаданных GX_OBJECT класса управления, делая их доступными на уровне приложения.

### Используется на страницах приложения

После успешной регистрации разработчики приложений могут использовать его в шаблонах страниц в качестве встроенных элементов управления:```xml
<!-- 以 progress-ring 组件为例 -->
<progress-ring
  class="ring"
  :value="progress"
  @completed="onDone">
</progress-ring>
```Здесь `:value="progress"` привязывает свойство value элемента управления к данным приложения `progress`; `@completed` прослушивает событие `completed`, предоставляемое элементом управления. Фреймворк автоматически преобразует значения JavaScript в свойства C++ и обратно, и разработчикам не нужно писать какой-либо «связывающий код».

### Имя пользовательского компонента

По умолчанию элементы управления регистрируются с именем класса. Если имя класса не подходит напрямую в качестве имени компонента, при регистрации можно указать собственное имя:```cpp
// Зарегистрируйте VendorWaveformGraph как WaveformGraph и напишите <waveform-graph> в шаблоне
kit.installWidget<VendorWaveformGraph>("WaveformGraph");
```PascalCase, соответствующий стиль имен классов C++.

### Преобразование имен C++ ↔ UX

Имя тега компонента соответствует имени при регистрации (по умолчанию используется **имя класса**, объявленное `GX_OBJECT`, или имя пользователя, указанное при регистрации). записи принято использовать шину (кебаб-регистр). имена во время компиляции**:

- Имя тега: kebab-case в шаблоне ↔ PascalCase зарегистрированного имени. Например, `<progress-ring>` соответствует классу `ProgressRing`.
— Имя атрибута: kebab-case в шаблоне ↔ CamelCase в C++. Например, «ring-color» соответствует атрибуту «ringColor».

C++, шина описания — это всего лишь соглашение о написании бокового шаблона, которое преобразуется в ux, а затем закрепляется.

Та же метка PascalCase и атрибут CamelCase, что и C++, также могут использоваться в компонентах UX, см. [Спецификация именования компонентов](/tutorials/name-spec.md).

## Экспорт свойств и событий

GX_PROPERTY`, GX_PROPERTY`, GX_PROPERTY` правила:

- Имя атрибута — это имя атрибута в компонентном фрейме, и они напрямую соответствуют другу.
- Свойствам, объявленным с помощью установщиков (`set xxx`), приложение может присваивать значения.
- Свойства, объявленные с помощью метода получения (`get xxx`), могут быть прочитаны в приложении.
- Сигнал xxxChanged`

Например, следующие полные свойства объявления:```cpp
класс ProgressRing: публичный виджет {
    GX_OBJECT
публика:
    GX_PROPERTY(целое значение, получить значение, установить setValue, значение сигналаChanged)
    GX_PROPERTY(Цвет кольцаЦвет, получение цвета кольца, установка setRingColor)
    GX_PROPERTY(bool showLabel, получить showLabel, установить setShowLabel)
    // ...
};
```Соответствующее использование на уровне приложения:```xml
<кольцо прогресса
  :value="jobProgress"
  цвет-кольца="#409EFF"
  :show-label="истина">
</прогресс-кольцо>
```CamelCase в C++: `ring-color` → `ringColor`, `show-label` → `showLabel` (преобразование прогресса производства ux, см. выше). `:value` и `:show-label` — это активирующие привязки (значения — это выражения), а литералы типа `ring-color="#409EFF"` — статические назначения.

### Экспорт событий

События экспортируются через свойства с изменениями сигналов вместо прямого экспорта членов Signal<>`.

1. Объявить член Signal<...>` (используемый внутри C++);
2. Добавьте ссылку на него в поле «сигнал» GX_PROPERTY.

Ключевое: имя события, отслеживаемое приложением, является атрибутом имени, а не именем члена сигнала.

### Событие изменения атрибута со значением```cpp
класс ProgressRing: публичный виджет {
    GX_OBJECT
публика:
    целое значение () константа;
    недействительный setValue (int v);

    Signal<int> valueChanged; // Внутренний сигнал, это имя не видно приложению
    GX_PROPERTY(целое значение, получить значение, установить setValue, значение сигналаChanged)
};
```Сторона приложения использует `@property name` для прослушивания изменений, поэтому здесь вместо `@value-changed` записывается `@value` (имя свойства): Хотя член сигнала вызывает `valueChanged`, имя события, по-видимому, всегда является именем свойства `value`.```xml
<progress-ring :value="progress" @value="onProgressChanged"></progress-ring>
```Это полностью соответствует элементам управления платформы. Изменено имя свойства `value` (`@value` или двустороннюю привязку `::value`).

### Чистое событие без значения

Для событий, которые не имеют значения и представляют собой лишь «что-то произошло» (например, «завершение»), которые имеют только сигнал и не имеют значения для чтения-записи:```cpp
Сигнал<> завершен; // Генерируется, когда прогресс завершен
GX_PROPERTY(invalid_t завершен, сигнал завершен)
```Сторона приложения может прослушивать следующим образом (без значения событий):```xml
<progress-ring @completed="onDone"></progress-ring>
```Вы не можете объявить GX_PROPERTY как тип void, даже если он вообще не имеет get/set, поэтому используйте valid_t в качестве типа-заполнителя. его как конкретный тип и метод расчета get — параметр типа Signal<T>` не получает автоматически значение событий, но всегда берется из свойств получения метода.

::: предупреждение `Signal<>` не становится событием автоматически
Signal<>` и не ссылаетесь на него с помощью Signal` ни в одном `GX_PROPERTY`, этот сигнал нельзя будет отслеживать на стороне приложения с помощью `@some-event`. будет обеспечиваться только «сигнал изменения свойства», то есть поле «сигнал», поскольку событие, а имя события всегда происходит из имени свойства.
:::

## Перечисления и типы структур

Если тип атрибута или метод параметра представляет собой пользовательское перечисление или формулу C++, его можно экспортировать вместе с аннотацией `GX_ENUM`/`GX_STRUCT`. автоматическое определение типов преобразования без необходимости написания кода JavaScript, структура в виде строковых констант на боковой стороне JavaScript, структура в виде литеральных объектов:```cpp
класс ProgressRing: публичный виджет {
    GX_OBJECT
публика:
    // Будьте осторожны при определении псевдонима для значения, иначе сторона JavaScript будет использовать
    // Имена «сплошные»/«пунктирные» вместо ожидаемых «сплошных»/«пунктирных»
    перечисление GX_ENUM LineStyle {
        Твердый GX_ALIAS («твердый») = 0,
        Пунктирный GX_ALIAS («пунктир»),
    };
    // Обратите внимание на прописание в структуре значений по умолчанию, чтобы избежать неопределенных полей при создании на стороне JavaScript.
    struct GX_STRUCT Range { int min = 0; интервал Макс = 100; };

    GX_METHOD void setRange (const Range &range);

    GX_PROPERTY(LineStyle lineStyle, получить lineStyle, установить setLineStyle)
};
``````xml
<progress-ring line-style="dashed"/>
``````js
this.$element('ring').setRange({ мин: 0, макс: 100 });
```Полную семантику, такую ​​как псевдонимы перечисления, рассмотрение структурных полей, вложенные признаки и т. д. д., см. в разделе [Система объектов · Отражение сложного типа] (./object-system.md#Отражение сложного типа), которое здесь не будет подробно описано.

::: предупреждение Не забудьте отметить
Если атрибуты обязательно соответствуют требованиям `GX_ENUM`/`GX_STRUCT`, JavaScript не может быть использован и не будет сообщений об нужных компиляциях.
:::

## Размещение дочерних элементов управления (элементы управления типа контейнера)

Если элементу управления необходимо связать субконтент, объявленному приложению, вам нужно реализовать его только как элемент управления контейнера: сторона C++ отвечает за расположение субэлементов управления, а платформа автоматически создает субкомпоненты, вложенные в шаблон, как в субэлементах управления, так и смонтирует их под ними. вложенные теги в шаблоне автоматически становятся дочерними элементами управления.

Существует два способа реализации макета контейнера (подробности см. в разделе «Макет и размер» [Руководства по разработке элементов управления] (./widget.md):

- setLayout(new FlexLayout())`;
- Или переопределите `layoutEvent()`, где нужно перебрать `children()` и вручную сохранить геометрию каждого дочернего элемента управления.

На уровне приложения просто вкори его как вложенный подтег (здесь карточка-панель — это контейнерный элемент управления, реализованный и зарегистрированный разработчиком, а «текст» — встроенный элемент управления):```xml
