# Glyphix OS: Canvas API
**Проект:** PurrGo / DT G1 (ATS3085S)
**Статус:** Фактологически подтверждено на эмуляторе, на первом устройстве требуется дополнительная проверка.

---

## 1. Системные особенности работы Canvas API
1. **Выполняется через метод вызова `getContext('2d')` (или `getContext()`) в родном элементе `<canvas>` в фазе жизненного цикла `onReady`.
2. **Механизм непрозрачного указателя (прокси-сервер C++):** Контекст объекта представляет собой прокси-обертку над нативным C++, представляет собой графический конвейер.
3. **Опасность проверки `if (ctx.method)`:** Попытка проверки наличия метода перед вызовом всегда возвращает `true` (функцию-обертку). Исключаю `TypeError: not a function` и крашу JS-контекст.

## 2. Итоговая матрица поддержки API

### 2.1. Поддерживаемые методы и свойства

| Категория | Поддерживаемые вещества | Применение в навигаторе PurrGo |
| :--- | :--- | :--- |
| **Свойства стиля** | `fillStyle`, `strokeStyle`, `lineWidth` | Управление цветовым треком, кислородом, текстом и более тонкими линиями |
| **Базовые фигуры** | `fillRect`, `strokeRect`, `rect`, `fill` | Очистка кадра (`fillRect`), отрисовка плашек и фонов |
| **Контуры (Путь)** | `beginPath`, `moveTo`, `lineTo`, `stroke` | Отрисовка ниток маршрута (Polyline) и векторных изображений |
| **Кривые** | `arc`, `arcTo`, `bezierCurveTo`, `quadraticCurveTo` | Отрисовка маркеров POI («дуга»), округлостей и мерок компаса |
| **Трансформации** | `сохранить`, `восстановить`, `перевести`, `повернуть`, `масштабировать` | Аппаратный поворот и поворот холста по азимуту движения |
| **Текст** | `заполнитьТекст` | Прямой рендер расстояния, скорости и подсказок на Canvas |

### 2.2. Отсутствующие методы

| Отсутствующий метод | Причина / Альтернатива (Резервный вариант) |
| :--- | :--- |
| `clearRect` | **Критично.** Заменен заливкой фонового цвета: `ctx.fillRect(0, 0, width, height)` |
| `эллипс` | Эмулируется через `arc()` |
| `трансформировать` | Использовать применения `translate()` и `rotate()` |
| `strokeText`, `measureText` | Используйте только `fillText()`. |
| `getImageData`, `putImageData` | Прямая работа с пиксельным буфером на JS недоступна |
| `клип` | Маскирование отрезанием недоступно |
| `createLinearGradient` | Градиенты не применяются.

##3. Архитектурные преимущества подтвержденного API

1. **Аппаратные преобразования («поворот» / «перевод» / «сохранение» / «восстановление»):**
   Наличие этих методов позволяет полностью выиграть от ручной тригонометрии поворота векторов на JS (`Math.cos`/`Math.sin`). `translate(cx, cy)` и повернуть на угол азимута `rotate(header)`.

2. **Отрисовка кривых (`arc`/`arcTo`):**
   Проверьте круговые маркеры текущего местоположения, промежуточные точки (Waypoints), а также элементы интерфейса (шкалу компаса, спидометр).

3. **Прямой рендеринг текста (`fillText`):**
   Убирает необходимость разместить оверлеи из Flexbox-тегов `<text>` на поверхности `<canvas>`, уменьшив количество узлов в MCU.

## 4. Каноническая очистка шаблонов и отрисовка кадра```javascript
renderFrame() {
  // 1. Очистка экрана (Замена отсутствующему clearRect)
  this.ctx.fillStyle = '#000000';
  this.ctx.fillRect(0, 0, 466, 466);

  // 2. Сохранение состояния матрицы трансформации
  this.ctx.save();

  // 3. Сдвиг центра координат и поворот холста под азимут (Heading)
  this.ctx.translate(233, 233);
  this.ctx.rotate(this.userHeading);

  // 4. Отрисовка объектов (курсор/трек) относительно нового центра
  // ...

  // 5. Восстановление исходного состояния матрицы
  this.ctx.restore();

  // 6. Вывод статичной телеметрии поверх кадра
  this.ctx.fillStyle = '#00ff00';
  this.ctx.fillText('150m', 200, 420);
}
```
