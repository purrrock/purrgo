## 1. Критичные и высокие приоритеты

- [ ] **Таймаут фикса GNSS** (`app_fsm.c`). `valid` никогда не сбрасывается: если приёмник замолчал, UI и логгер считают позицию валидной. Добавить `last_rmc_ms` и сброс `valid` через 3–5 с.
- [ ] **Ошибки записи на SD не обрабатываются** (`fs_hal_stm32.c`, `track_logger.c`). `purrgo_fs_sync` возвращает `void`, `purrgo_fs_close` и `purrgo_fs_write` не сообщают об ошибках, результат записи в `flush_buffer` игнорируется. Вернуть `bool`/код ошибки, переводить логгер в `ERROR` и пробовать переоткрыть файл. Закрывает пункт TODO «тест заполненной microSD».
- [ ] **Атомарное сохранение конфига** (`config.c`, `purrgo_config_save`). Сейчас `FA_CREATE_ALWAYS` усекает файл до записи. Писать во временный файл, `f_sync`, затем `f_rename`.
- [ ] **Политика перерисовки e-ink.** Любая смена скорости, высоты, числа спутников (`purrgo_app_update` → `ui_dirty`) и любое нажатие кнопки (даже нераспознанной, `purrgo_app_handle_button`) вызывает перерисовку. Ввести минимальный интервал между обновлениями и пороги изменения значений. Для Trip computer особенно важно.
- [ ] **Единый владелец dirty-флагов.** `ui_render_map` чистит `map_dirty` только при `map_success`, а `stm32_app.c` чистит всё безусловно. Выбрать один механизм; неудачный рендер карты сейчас не повторяется.

## 2. Ошибки и недочёты средней важности

### Карта (`map.c`, `map_render.c`, `gfx`)
- [ ] Повторные открытия файлов карты на каждом кадре, если слой включён, а файла нет (`map_sync_files`); каждый вызов пишет в UART. Запоминать неудачу и не повторять до смены каталога/конфига.
- [ ] `purrgo_map_render_viewport` возвращает `landuse_success && roads_success && poi_success`, но `poi_success` всегда `true`, а признаки успеха ставятся по факту открытия файлов, а не по результату отрисовки.
- [ ] Насыщение координат в `project_to_screen`: результат клампится в `int16`, при крупном масштабе вершины далеких полигонов искажают наклон рёбер (неверная заливка водоёмов и лесов). Либо `int32` в `gfx_point_t`, либо отсечение полигона до заливки.
- [ ] `gfx_fill_compound_polygon`: O(строки × рёбра); при `nodes >= GFX_MAX_POLYGON_NODES` функция делает `return`, и полигон остаётся нарисованным частично.
- [ ] Путь `map_dir` длиннее 256 байт молча обрезается (`current_map_dir[256]` против буфера конфига 288); возвращаемое значение `purrgo_snprintf` не проверяется.

### Трек и время (`track_logger.c`, `purrgo_time.c`)
- [ ] Имя трека `epoch(local) - 820454400` без проверки: при времени до 2026 года будет `uint32`-underflow; при совпадении имени `FA_CREATE_ALWAYS` затирает существующий файл. Использовать UTC и проверку существования файла.
- [ ] Порог 5 м сравним с шумом GNSS на стоянке (трек «заштриховывается»); нет фильтра по HDOP, числу спутников, скорости и фильтра выбросов; в режиме EXPEDITION (100 м) срезаются повороты (нет критерия по углу курса).
- [ ] В полночь `purrgo_logger_stop()` очищает RAM-буфер, и видимый трек исчезает с экрана.
- [ ] `f_sync` на каждом заполнении буфера (каждые ~4 точки): синхронизировать раз в 60 с или 50 точек. Переменная `last_sync_time` задана, но не используется.
- [ ] Устаревший комментарий «8192 точки = 64 КиБ», а `TRACK_RAM_MAX_POINTS = 1024`.

### GNSS (`gnss.c`, `gnss_adapter.c`)
- [ ] GSA от разных систем (GP/GL/BD) перезаписывают `fix_type`/`hdop` по очереди; принимать по `talker`/`system id` (актуально для G10A F30).
- [ ] Вендорные команды `$PCAS…` (CASIC) зашиты в общий `gnss_io.c`. Вынести в отдельный платформенный/приёмник-специфичный слой.
- [ ] Сверить число полей `$PCAS03` с даташитом AT6558R (в строке 13 полей).
- [ ] При UART-ошибке (`HAL_UART_ErrorCallback`) DMA перезапускается и непрочитанные данные теряются; сначала читать остаток, затем перезапускать.

### Прочее
- [ ] `app_fsm.c:136`: `purrgo_action_t` передаётся как `purrgo_btn_t` (тихая путаница типов).
- [ ] Неиспользуемые переменные `changed` и `reason` в `ui_map.c`, неиспользуемые параметры в `trip_computer.c`; пройтись по предупреждениям `-Wconversion` в `gfx` и `ui` (~140 штук, в основном `int → int16_t`).
- [ ] `purrgo_snprintf`: нет `%f`, `%zu`, `%lld`; неизвестные спецификаторы не потребляют `va_arg`, и следующие аргументы сдвигаются. Добавить `__attribute__((format(printf, …)))`.

## 4. Оптимизация для embedded

### Энергопотребление
- [ ] Главный цикл заканчивается `__WFI()`, но HAL-тик 1 кГц будит MCU 1000 раз в секунду. Нужны tickless/Stop-режим, пробуждение по RTC/EXTI, обработка GNSS через IDLE-прерывание вместо опроса.
- [ ] `EPD_2IN7_V2_ReadBusy` — busy-loop на время обновления панели (секунды). Заменить на EXTI по BUSY и `WFI` (драйвер в сабмодуле: wrapper или форк).
- [ ] `HAL_Delay(300)` на заставке и два полных refresh при старте: оставить один.
- [ ] Логгер на UART блокирующий, без уровней и без отключения в релизе, плюс дёргает светодиод `PC13` на каждое сообщение. Ввести `PURRGO_LOG_LEVEL` на этапе компиляции и DMA-кольцо.
- [ ] `power_off` переводит в Standby только MCU; GNSS и SD остаются запитанными (нужен аппаратный ключ питания).

### SPI и SD
- [~] SD на SPI2: сделан делитель 4 (патч 0002). Проверить целостность сигнала на реальных проводах и при желании перейти на делитель 2. Планируется переход на SDIO.
- [ ] Обмены SD и дисплея идут через блокирующий `HAL_SPI_Transmit` побайтово (в драйвере Waveshare CS дёргается на каждый байт). Использовать DMA для 512-байтных блоков SD и кадра дисплея.
- [ ] Сверить допустимую частоту SPI контроллера панели по даташиту (сейчас ~10,5 МГц, подтверждено работой; можно ли выше — не выяснялось).

### FatFs (`ffconf.h`)
- [ ] `_FS_TINY 0`: в каждом `FIL` свой 512-байтный буфер (14 слотов ≈ 7,8 КБ RAM) плюс LRU-кэш 32 × 528 Б ≈ 16,9 КБ. Чтение идёт целыми секторами, поэтому достаточно `_FS_TINY 1` и меньшего `STM32_MAX_FILES` (используется ≤ 9 файлов).
- [ ] `_USE_FASTSEEK 1` включён, но таблица CLMT (`fil.cltbl`) не создаётся: быстрый seek не работает. Создавать CLMT при открытии файлов карты (с запасным вариантом при сильной фрагментации).
- [ ] `_CODE_PAGE 855` при `_USE_LFN 1`: оценить размер таблиц `ccsbcs.c` по map-файлу.

### Рендеринг
- [ ] `project_to_screen`: два 64-битных деления на точку (`__aeabi_ldivmod`). Посчитать масштаб один раз за кадр (Q16/Q32) и применять умножение.
- [ ] `gfx_draw_hline` вызывает `draw_pixel` по колбэку на каждый пиксель. Добавить колбэк `fill_span`, заполняющий байты 2-bpp.
- [ ] В `map_render_feature` `switch (style)` и два `gfx_set_color` стоят внутри цикла по сегментам; вынести за цикл.
- [ ] Чтение геометрии порциями по 64 байта (`PURRGO_MAP_READ_CHUNK_SIZE`): читать секторами по 512 Б.
- [ ] Заголовки PGO/SQT перечитываются на каждый слой в каждом кадре; кэшировать после открытия.
- [ ] Имя объекта читается отдельным seek + read на 100 байт на каждую подпись.
- [ ] Проверить итоговый `.elf` на soft-float helpers (`arm-none-eabi-nm | grep __aeabi_[fd]`); ядро целочисленное, но `minmea.h` содержит inline-функции с `float`.

## 5. Best practices и процесс

- [ ] **Тесты.** Автоматические тесты удалены (коммит `7a9ef1d`), остался `tests/audit_maps.py`. Нужны минимум: host-тест парсера карты на корректных и повреждённых файлах, тест кольцевого буфера GNSS и NMEA-парсера на записанных логах, тест `purrgo_time`/`track_logger` на границах (полночь, `year < 26`).
- [ ] **CI.** Не настроен. Добавить сборку ядра и STM32, прогон host-тестов, ASan/UBSan на PC, `cppcheck`/`clang-tidy`.
- [ ] **Флаги сборки.** Включить `-Wall -Wextra -Wshadow -Wformat=2 -Wconversion -Wdouble-promotion`, `-fstack-usage`, `-ffunction-sections -fdata-sections`, `--gc-sections`, `-Wl,--print-memory-usage`.
- [ ] **Мусор в репозитории.** Пустой файл `git` в корне`; опечатка `*.userossc` в `.gitignore` и шаблон `.osm` вместо `*.osm`; закоммичены `apps/stm32/.../.settings/*.json` и `.clangd`, хотя те же пути в `.gitignore`; вендорный HAL (~1,8 млн строк) лучше подтягивать пакетом CubeMX или сабмодулем.
- [ ] **Документация.** Привести README и `architecture.md` в соответствие с реальной структурой; в `TODO.md` нумерация разделов пропускает 3, пункты «Завершение PC-версии» пустые.
