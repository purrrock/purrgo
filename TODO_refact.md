## 4. Оптимизация для embedded

### Энергопотребление
- [ ] Главный цикл заканчивается `__WFI()`, но HAL-тик 1 кГц будит MCU 1000 раз в секунду. Нужны tickless/Stop-режим, пробуждение по RTC/EXTI, обработка GNSS через IDLE-прерывание вместо опроса.
- [ ] `EPD_2IN7_V2_ReadBusy` — busy-loop на время обновления панели (секунды). Заменить на EXTI по BUSY и `WFI` (после замены драйвера на epd4g).
- [ ] `HAL_Delay(300)` на заставке и два полных refresh при старте: оставить один.
- [ ] Логгер на UART блокирующий, без уровней и без отключения в релизе, плюс дёргает светодиод `PC13` на каждое сообщение. Ввести `PURRGO_LOG_LEVEL` на этапе компиляции и DMA-кольцо.
- [ ] `power_off` переводит в Standby только MCU; GNSS и SD остаются запитанными (нужен аппаратный ключ питания).

### SPI и SD
- [ ] SD (SPI2) работает в режиме опроса, без DMA. Передавать блок через GPDMA, если скорость чтения карт окажется недостаточной (см. `docs/SD_SPI_MODE.md`).
- [ ] Обмен E-Ink идёт через блокирующий `HAL_SPI_Transmit` побайтово (в драйвере Waveshare CS дёргается на каждый байт). Использовать DMA для кадра дисплея (после замены драйвера на epd4g).
- [ ] Сверить допустимую частоту SPI контроллера панели по даташиту (сейчас ~10,5 МГц, подтверждено работой; можно ли выше — не выяснялось) (после замены драйвера на epd4g).

### FatFs (`ffconf.h`)
- [ ] `_FS_TINY 0`: в каждом `FIL` свой 512-байтный буфер (14 слотов ≈ 7,8 КБ RAM) плюс LRU-кэш 32 × 528 Б ≈ 16,9 КБ. Чтение идёт целыми секторами, поэтому достаточно `_FS_TINY 1` и меньшего `STM32_MAX_FILES` (используется ≤ 9 файлов).
- [ ] `_USE_FASTSEEK 1` включён, но таблица CLMT (`fil.cltbl`) не создаётся: быстрый seek не работает. Создавать CLMT при открытии файлов карты (с запасным вариантом при сильной фрагментации).
- [ ] `_CODE_PAGE 855` при `_USE_LFN 1`: оценить размер таблиц `ccsbcs.c` по map-файлу.

### Рендеринг
- [ ] `project_to_screen`: деления теперь 32-битные для почти всех точек (результат идентичен 64-битному, проверено тестом); полный переход на умножение на масштаб кадра (Q16/Q32) не делался: он менял бы округление и, значит, пиксели. Замерить на железе, остаётся ли проекция заметной в профиле кадра.
- [ ] `fill_span` подключён для `gfx_draw_hline` и `gfx_fill_rect` (STM32: `stm32_fill_span_cb`, целые байты 2-bpp - `memset`); остальные примитивы (`gfx_draw_line`, окружности, текст) по-прежнему идут через `draw_pixel`. Замерить выигрыш на железе (заливка полигонов карты).
- [x] Чтение геометрии порциями по 64 байта (`PURRGO_MAP_READ_CHUNK_SIZE`): читать секторами по 512 Б. **Сделано (патч 0025):** `map_mlp.c` читает заголовок, таблицу частей и точки одним буферизованным потоком (буфер 512 Б в `map_mlp_iter_t`, +448 Б стека в `map_render_feature`). Пока размер объекта неизвестен, читается остаток текущего сектора, затем порции до 512 Б, но не дальше конца объекта: лишние сектора карты не читаются (большинство объектов мельче сектора). Тест `test_map_mlp_stream`. Выигрыш на железе не измерялся.
- [x] Имя объекта читается отдельным seek + read на 100 байт на каждую подпись. **Сделано (патч 0025):** читается только `sizeof(name_buf) - 1` = 63 байта (остальное всё равно отбрасывалось), реже захватывается следующий сектор `.db`. Один seek + read на подпись остаётся: записи разных объектов лежат вразнобой, а повторное чтение того же сектора FatFs берёт из буфера файла.
- [ ] Проверить итоговый `.elf` на soft-float helpers (`arm-none-eabi-nm | grep __aeabi_[fd]`); ядро целочисленное, но `minmea.h` содержит inline-функции с `float`. **Подготовлено (патч 0025):** `tools/check_softfloat.sh <файл.elf>`; в среде патча нет `arm-none-eabi-gcc`, прошивка не собиралась, нужно запустить у себя.
