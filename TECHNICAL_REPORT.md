# Технический отчет по проекту PurrGo

## 1. Структура файлов проекта
Проект представляет собой приложение для смарт-часов (WearOS / Glyphix OS) и имеет следующую структуру:
* `com.purr.go/` — основная директория исходного кода приложения.
  * `src/app.js` — глобальный обработчик жизненного цикла приложения (содержит `onCreate`, `onShow`, `onHide`, `onDestroy`, `onError`, `onPageNotFound`).
  * `src/manifest.json` — конфигурация пакета, манифест приложения. Включает название (`PurrGo`), версию (`0.1.0`), настройки экрана часов (`designWidth: 466`), конфигурацию роутера (точка входа — страница `main`), а также запрашиваемые системные разрешения:
    * `watch.permission.LOCATION`
    * `watch.permission.ACCESS_SENSORS`
    * `watch.permission.FOREGROUND_SERVICE`
  * `src/main/` — директория главной страницы приложения (роут `main`).
    * `index.ux` — главный файл пользовательского интерфейса, содержащий шаблон (`<template>`), стили (`<style>`) и логику (`<script>`). Основной элемент UI — `<canvas>` для отрисовки карты/маршрута.
    * `mock_track.js` — локальный модуль с замоканными GPS-координатами маршрута.

В корне также находится директория `/docs`, содержащая спецификации Glyphix OS. В частности, `glyphix_canvas_spec.md` описывает жесткие ограничения работы с Canvas API в данной ОС (отсутствие `clearRect`, поддержка только определенных трансформаций и прямого вывода текста).

## 2. Реализация плоской проекции (Equirectangular Projection) в index.ux
Для перевода сферических GPS-координат (WGS84) в плоские экранные (пиксели) в приложении используется функция `projectToCanvas(lat, lon)`, реализующая равнопромежуточную (Equirectangular) проекцию. Это крайне быстрый алгоритм, подходящий для маломощных MCU:
1. Вычисляется широта пользователя в радианах: `latRad = userLat * (Math.PI / 180)`.
2. Вычисляются дельты координат от текущего местоположения: `deltaLon` и `deltaLat`.
3. Координата `X` масштабируется с учетом сжатия меридианов по широте (компенсация искажений): `x = cx + (deltaLon * zoomLevel * Math.cos(latRad))`.
4. Координата `Y` просто масштабируется, но при этом инвертируется ось (так как в GPS Север — это +Y, а в Canvas — ось Y направлена вниз): `y = cy - (deltaLat * zoomLevel)`.
Здесь `zoomLevel` выступает масштабным коэффициентом (в коде равен 60000).

Само отображение реализовано с использованием разрешенных аппаратных трансформаций Canvas (согласно документации `/docs/glyphix_canvas_spec.md`): вместо ручного пересчета повернутых векторов холст аппаратно сдвигается и вращается через методы `translate(cx, cy)` и `rotate(-userHeading)`.

## 3. Подключенные модули (Модули работы с треком)
На данный момент для работы с треком подключен локальный модуль:
* `mock_track.js` (замоканный массив точек `mockRoutePoints`). Он импортируется напрямую в `index.ux` (`import { mockRoutePoints } from './mock_track.js';`) для обхода ограничений загрузки файлов ресурсов.

Системные модули Glyphix (такие как `@system.geolocation`, `@system.compass`, `@system.file`) для реального получения координат и азимута пока не подключены напрямую в коде `index.ux`, однако в `manifest.json` для них уже запрошены необходимые пермиссии.
